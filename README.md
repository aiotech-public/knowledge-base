# База знаний AIO

Официальная база знаний по продукту AIO — та же, на которой работает AI-ассистент внутри
`app.aio.tech`. Здесь она выложена в исходном виде: набор markdown-документов, которые можно
читать как обычную документацию — или скачать и загрузить в собственную RAG-систему, внутренний
поиск или ассистента.

Релиз `v2026.08.12` · документов: 69 · обновлено 2026-08-12

## Что внутри

| Раздел | Что это |
|---|---|
| `context/` | архитектура AIO |
| `models/` | объекты системы: Tenant, Campaign, Flow, Visit, Conversion, Domain, Landing… |
| `mechanics/` | как объекты работают вместе: путь визита, атрибуция расходов, PWA, уведомления |
| `how-to/` | процедуры «как сделать X» |
| `heuristics/` | правила большого пальца при запуске |
| `reference/` | глоссарий, плейсхолдеры, SDK и макросы, лимиты, карта интерфейса |
| `faq/` | частые вопросы |

Служебные файлы в корне: [INDEX.md](INDEX.md) — указатель по всем документам,
[CHANGELOG.md](CHANGELOG.md) — что изменилось в каждом релизе, [MANIFEST.json](MANIFEST.json) —
машинный индекс (путь, заголовок, `sha256` и дата изменения каждого документа), [LICENSE](LICENSE).

Язык — русский; названия объектов интерфейса — на английском в обратных кавычках, ровно как они
подписаны в продукте (`Backfix`, `Flow State`, `Distribution`).

## Как читать

- [INDEX.md](INDEX.md) — оглавление: раздел → документ → одна строка о чём он.
- Знакомство с системой с нуля: [context/architecture.md](context/architecture.md) →
  [models/domain-model.md](models/domain-model.md) → [mechanics/visit-lifecycle.md](mechanics/visit-lifecycle.md).
- Точные названия полей, статусов и терминов — [reference/glossary.md](reference/glossary.md).

## Формат документов

- Имя файла — стабильный идентификатор документа (`visit-lifecycle.md`): при обновлении текста
  оно не меняется, переименования фиксируются в `CHANGELOG.md` и `MANIFEST.json`.
- Один H1 на документ, дальше секции H2/H3. Каждая секция самодостаточна: начинается с самого
  факта и не превышает ~1400 символов.
- Ссылки между документами — относительные, кликаются прямо на GitHub.
- У каждого документа frontmatter:

```yaml
id: visit-lifecycle          # стабильный идентификатор, равен имени файла
title: …                     # заголовок
description: …               # одна строка о чём документ
doc_type: mechanic           # model | mechanic | context | how-to | playbook | heuristic | reference | faq
builds: [erp, mtk]           # к какому виду продукта относится документ
related: [visit, flow-model] # соседние документы по теме
language: ru
updated: 2026-08-11          # дата последнего изменения документа
```

## Как использовать базу у себя

База отдаётся как есть — дальше она ваша: держите зеркалом для команды, положите во внутреннюю
вики, подключите к поисковому движку или отдайте своему ассистенту. Формат рассчитан в том числе
на индексацию в RAG:

1. **Резать можно по заголовкам H2/H3** — каждая секция осмыслена сама по себе, отдельный
   сплиттер не нужен.
2. **`description` из frontmatter** полезно приклеивать к каждому фрагменту при индексации — он
   даёт фрагменту контекст всего документа.
3. **Переиндексация — инкрементальная**: по [MANIFEST.json](MANIFEST.json) видно, у каких
   документов изменился `sha256`, — переиндексируются только они.
4. **Заголовки сформулированы словами спрашивающего**, поэтому по базе хорошо работает и обычный
   полнотекстовый поиск, не только векторный.
5. **Нужна фиксированная версия** — берите git-тег релиза, а не `main`.

## Обновления

База обновляется релизами вслед за продуктом: git-тег `vГГГГ.ММ.ДД` + запись в
[CHANGELOG.md](CHANGELOG.md), что добавлено, изменено и удалено.

Репозиторий собирается автоматически, поэтому прямые правки и pull request-ы в него не
принимаются — их перезапишет следующий релиз. Нашли ошибку или неточность — напишите в поддержку
AIO, исправление приедет ближайшим релизом.

## Версия продукта и актуальность

> **База обновляется вслед за продуктом, а не наоборот.** AIO меняется чаще, чем выходят релизы
> базы, поэтому свежие изменения продукта попадают сюда с задержкой — до ближайшего релиза.
> Расхождение с интерфейсом на недавней фиче — ожидаемый порядок обновления, а не ошибка базы:
> смотрите дату релиза в [CHANGELOG.md](CHANGELOG.md), актуальное поведение сверяйте с самим
> продуктом.

Документация описывает облачный AIO (`app.aio.tech`) в состоянии на дату релиза. Если ваш AIO
развёрнут по другому адресу — примеры вида `https://app.aio.tech/api/v1/...` читайте со своим
хостом, а состав доступных разделов сверяйте со своей версией: поле `builds` в frontmatter
показывает, к какому виду продукта документ относится.
