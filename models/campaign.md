# Campaign — концепт

> Концепт: что это, как устроено, как связано. Пошаговые процедуры (создать, Link Generator, Update Costs, FB/AIO Meta) — в [how-to/campaigns.md](../how-to/campaigns.md). Где в UI — [reference/ui-map.md](../reference/ui-map.md): в ERP `Tracker → Campaigns`, в MTK — `Campaigns` в основном меню.

## Суть в одном абзаце

**Campaign — это запускаемый инстанс Flow.** Flow задаёт *путь* (граф шагов), а кампания — это конкретный запуск этого пути: она привязана к **одному Flow**. Для генерации рекламной tracking-ссылки выбирают эту кампанию, **Link-домен** и **Source**. По клику на ссылку в кампании рождается визит. Всё, что дальше с этим визитом происходит (показы, фильтрация, лиды, косты, конверсии), **агрегируется обратно на кампанию** — поэтому кампания это ещё и «единица отчётности», вокруг которой крутится вся аналитика медиабаера.

## Как это работает на самом деле

### 1. Кампания = инстанс, Flow = класс

Полезная аналогия из программирования: **Flow — это класс (шаблон), Campaign — его экземпляр.** Один Flow переиспользуется десятками кампаний. Это намеренно: байер один раз собирает «правильный» путь (Source → Filter → Preland → Offer → Destination), а потом плодит под него кампании — по гео, по офферу, по крео — не пересобирая логику каждый раз.

Из этого вытекает ключевое свойство и ключевой подвох:
- **Свойство:** общая логика Flow используется кампаниями на нём. Настройки, переопределённые в кампании, сохраняют её собственные значения.
- **Гоча:** изменение общего Flow затрагивает существующие кампании, а выбранные в них лэнды не заменяются новым шаблоном автоматически. Для нового пути рекомендуется создать отдельный Flow и запускать с него новые кампании; при переводе старой кампании нужно проверить её настройки шагов. См. [models/flow-model.md](flow-model.md).

### 2. Edit Campaign = оверлей поверх шагов Flow

Когда открываешь `Edit Campaign`, в основной области видны **шаги привязанного Flow в виде карточек** — это и есть «инстанс» пути. Но редактируются не все настройки, а только те, что Flow разрешил трогать на уровне кампании — механика **`Settings Availability`** (`Campaign Template` / `Flow Only` / `Campaign Only`), детально — [models/flow-model.md](flow-model.md) → Settings Availability.

Поэтому два байера на одном Flow могут иметь разные лэнды/фильтр/дестинейшны в своих кампаниях — каждый правит свой оверлей, не ломая общий чертёж. Сам путь целиком виден, не уходя из редактора: рядом с селектом `Traffic flow` есть кнопка-глаз `Flow preview` — нередактируемая схема выбранного флоу полноэкранной модалкой. Что именно правится в Edit Campaign, как устроены карточки шагов и превью — [how-to/campaigns.md](../how-to/campaigns.md).

### 3. Ссылка — это «адрес» кампании, `cuuid` — её идентичность

Tracking-ссылку для рекламы собирает **Link Generator** из тройки `Campaign + Domain + Source`. В ссылке зашит **`cuuid` = UUID этой кампании** (и `suuid` = UUID source). По `cuuid` AIO определяет, *в какую кампанию* положить визит (агент принимает клик и передаёт параметры). Если в новом заходе не хватает `cuuid` или `suuid` после декодирования ссылки, атрибуцию нужно дополнить через `Default Query` домена или `Direct Traffic Distribution` (см. [mechanics/visit-lifecycle.md](../mechanics/visit-lifecycle.md)). Штатный путь прямого трафика в MTK — `Default Query` на каждом домене. Общая форма `Edit domain` также позволяет выбрать доступную существующую `Direct Traffic Distribution`; это не заменяет настройку её правил.

Одна кампания может породить **много ссылок** (разные домены, разные Source, разные `Launcher`-ы при multi-buyer) — но `cuuid` у них один. История ссылок живёт в `Edit Campaign → Link history` при наличии права `tracker.generated-links.view`.

### 4. Кампания — корень агрегации (деньги и аналитика)

Визиты, лиды, конверсии, косты — всё это «висит» на кампании, и вокруг неё крутится вся аналитика по деньгам. **Основной способ видеть косты и профит по FB — метрика `Meta Spend`** (движок `AIO Attribution Engine`): она считается на лету в момент отчёта, сшивает спенд Meta с трафиком на уровне `Campaign` / `Adset` / `Ad` (уровень выбирается кнопкой матчинга в тулбаре таблицы с Meta-метриками — иконка Meta + текущий уровень; по умолчанию `Campaign`, выбор хранится в браузере. Группировка или фильтр по Meta ID может задать свой уровень) и стоит рядом с revenue — профит и ROI по FB рассчитываются в отчёте по разрезам, для которых есть сопоставленные данные трафика и Meta, стратегию костов на кампании для этого выбирать не нужно. Разбор — [mechanics/meta-spend-allocation.md](../mechanics/meta-spend-allocation.md).

Здесь же, на кампании, живёт **`Costs update strategy`** — отдельный действующий способ заливки рекламных расходов в метрику `Costs` **на самих визитах** (для классического ROI-столбца в трекере). Он сосуществует с `Meta Spend`; по костам/профиту FB ориентируйся на `Meta Spend`, а перелив трогай, только когда нужен именно visit-level `Costs`:
- `Manual` — косты вносятся руками (`Update costs`: за период, по полю, сумма делится поровну между выбранными визитами, CPC задаёт одинаковую стоимость каждому визиту окна. Ограничение по полю применяется к сумме; в режиме CPC оно не применяется, [how-to/campaigns.md](../how-to/campaigns.md));
- `AIO Meta` / `Meta Account` / `Meta Campaign` / `Meta AdSet` — автоперелив FB-костов в метрику `Costs` с атрибуцией по соответствующему уровню FB-иерархии (`AIO Meta` = по `FB Ad ID`, самый точный уровень). В колонке `Cost Strategy` эти значения подписаны иначе: `AIO Meta` показывается как **`Meta Ad`**, `Meta AdSet` — как **`Meta Ad Set`**.

Автоперелив в visit-level `Costs` требует настроенной Meta-стратегии. `Manual` выбран по умолчанию; помимо ручного обновления, стоимость может прийти с параметром `cost` входной ссылки. `Meta Spend` рассчитывается отдельно и не зависит от стратегии костов кампании. Детали перелива, AIO Meta и ретро-окна атрибуции — [how-to/campaigns.md](../how-to/campaigns.md).

### 5. Часть полей кампании AIO проставляет сам — не руками

Несколько аналитических полей кампании AIO **пересчитывает по фоновому расписанию из свежего трафика**, поэтому они появляются и меняются сами, а не вводятся вручную:

- **`quality`** — доля нетрэш-трафика (`good / (good + bad)` в процентах) за скользящий последний час. Пересчёт сохраняет целое значение.
- **`detected_country`** — топ-страна нетрэш-трафика кампании за последний час.
- **`detected_source_uuid`** (аналитическая колонка `Detected source`) — источник кампании определяется сам по преобладающему трафику; при пересчёте выбирается самый частый `Source` среди нетрэш-визитов кампании за последний час (см. «Source vs Detected source» в [models/source.md](source.md)).
- **visit-level `Costs`** — заливаются автопереливом FB-костов, если настроена одна из Meta-стратегий костов (раздел выше).

`detected_country` и `detected_source_uuid` обновляются при наличии результата пересчёта. Если за окно нет подходящего трафика, сохраняется предыдущее значение.

Отсюда типовой вопрос «почему у меня само проставилось / когда обновится»: у этих полей есть лаг — свежий трафик отражается в них спустя несколько минут после того, как отработает соответствующий фоновой пересчёт. Список фоновых пересчётов AIO и их частота — *Что AIO проставляет и делает сам — автоматические обновления и их лаг*.

### Номер кампании (`human_id`) — формат вида `007567`

Помимо UUID у кампании есть короткий человекочитаемый номер **`human_id`** — номер, дополненный ведущими нулями минимум до 6 цифр, например `007567`. Именно его показывают таблицы и разбивки статистики (рядом с именем), и по нему удобно искать кампанию вместо длинного `cuuid`. Формат `#7567` = тот же номер без ведущих нулей. Номер не участвует в tracking-ссылке — в ней едет `cuuid` (UUID), а `human_id` только для человека в UI.

## Remarketing Campaign — второй тип кампании, без трафиковой части

Всё выше — про **трафиковую** кампанию. Кроме неё есть второй тип — **Remarketing Campaign**: она не принимает трафик, а рассылает сообщения по собранной аудитории визитов. У неё нет доменов, источников, ссылки, стратегий костов и traffic-фильтров — она указывает на флоу типа `Notifications` и редактируется тем же диалогом кампании, только без трафиковой части. Живёт в отдельном разделе `Marketing → Campaigns`; в MTK доступна с платным модулем `PWA + Push` и правом `marketing.campaigns.view` (вкладка `PWA → Campaigns`).

Права на неё **отдельные**: права трафиковых кампаний доступа к ремаркетингу не дают, их выдают отдельно. Как устроена, чем запускается и как собирается аудитория — [how-to/remarketing-campaigns.md](../how-to/remarketing-campaigns.md).

## Чем редактор кампании в MTK отличается от ERP?

**В MTK-билде кампания использует ту же базовую механику, но редактор ограничен** (MTK — это ограниченный вид того же тенанта, разбор — *Как устроен MTK-вид AIO: навигация, пресеты из шаблона и методы под типовые задачи*):

1. **Флоу только выбрать, не собрать.** Поле `Traffic flow` в `Edit Campaign` — это дропдаун с преднастроенными флоу: они приходят из шаблона тенанта, и набор зависит от вертикали (например, `1/2Step | Preland to Offer` в Finance, `PWA / OneLink` в iGaming, `Default 1Step Flow` в Sweeps — что клонируется из шаблона, [context/architecture.md](../context/architecture.md)). Создавать новые и редактировать существующие флоу в MTK нельзя — редактора флоу в этом виде нет. «Кампания = инстанс Flow» остаётся верным, только Flow берётся готовым.
2. **Нет выбора `Conversions AI` / `Metrics AI`.** Редактор кампании в MTK не предлагает эти AI-стратегии оптимизации.
3. **Нет панели `LP Splits`.** В MTK не редактируют сплиты элементов лэнда через эту панель. В блоке `Landing` кампании выбирают целые лэнды (`First` / `Weights`). Уже настроенные сплиты в HTML обрабатываются при показе лэнда.

В `Edit Campaign` остаются встроенный фильтр в блоке `AIO Filter` (его параметры), косты, домены и source. Вкладка `Sessions`, доступная в ERP при отдельном праве, в MTK не показывается. Где что лежит в MTK-навигации — *Как устроен MTK-вид AIO: навигация, пресеты из шаблона и методы под типовые задачи*.

## Как Campaign связана с остальными сущностями

- **Campaign → ровно один Flow** (путь). Наследует структуру + оверрайды шагов.
- **Campaign + Source → Link → Visit.** Визит входит по `cuuid`+`suuid`.
- **Campaign → Link-домен.** Обычно трекинговый; публичный домен может подменяться шагом `Domain-Change` внутри пути ([models/domain.md](domain.md)).
- **Campaign ← Visit / Conversion / Cost.** Корень роллапа всей статистики.
- **Campaign → шаги Flow** показываются карточками в `Edit Campaign` (оверлей по `Settings Availability`).

## Чем Campaign отличается от смежных понятий

| Не путать | Разница |
|---|---|
| **Campaign vs Flow** | Flow — переиспользуемый **чертёж** пути (States+Transitions). Campaign — **один запуск Flow**; для неё создают ссылки с выбранными доменом и Source. Один Flow → N кампаний. |
| **Campaign vs Source** | Source — пресет **происхождения** трафика (что ловить из URL). Campaign **использует** Source; трафик сама не «генерит», только определяет путь. |
| **Campaign vs Link** | Ссылка — **производное** (`Campaign + Domain + Source` → Link Generator). Одна кампания → много ссылок, один `cuuid`. |
| **Campaign vs «кабинет FB»** | В AIO кампания — это **трекерная** сущность (путь+ссылка+статистика), не рекламная кампания FB. FB-кампании живут в разделе `Meta`; привязываются для перелива костов в `Costs` (AIO Meta — действующий перелив в visit-level `Costs`; рекомендуемый способ по костам/профиту FB — метрика `Meta Spend`, [mechanics/meta-spend-allocation.md](../mechanics/meta-spend-allocation.md)). |

## Подводные камни Campaign — частые ошибки настройки

- **Для нового пути под активными кампаниями рекомендуется отдельный Flow.** При изменении общего Flow проверяют настройки шагов существующих кампаний.
- **`Copy campaign`** — штатный способ плодить варианты (то же на том же Flow, меняешь только оверлей).
- Visit-level `Costs` (классический ROI-столбец) пустой → проверь источник расходов: при `Manual` нужны ручное обновление или параметр `cost` входной ссылки; для автоперелива FB — настроенная Meta-стратегия и подключение соцки (для `By Meta Application` — через `Connect`). `Meta Spend` не требует стратегии костов кампании, но требует сопоставимых данных трафика и Meta.

## `Lock campaign to this domain` — привязать кампанию к одному домену

**По умолчанию кампания не ограничена одним Link-доменом.** Для обычного нового захода можно использовать другой рабочий домен своего тенанта; кампания и её инфраструктура должны быть действующими.

Toggle `Lock campaign to this domain` в `Edit Campaign` появляется после выбора `Link domain` и по умолчанию выключен. При включении новый обычный заход с другого домена отклоняется. Последующий шаг `Domain Change` может сменить публичный домен внутри пути визита.

Выбор нескольких доменов для этого ограничения не поддержан: настройка привязана к одному выбранному `Link domain`.
