# Campaign — концепт

> Концепт: что это, как устроено, как связано. Пошаговые процедуры (создать, Link Generator, Update Costs, FB/AIO Meta) — в [how-to/campaigns.md](../how-to/campaigns.md). Где в UI — [reference/ui-map.md](../reference/ui-map.md) → Tracker → Campaigns.

## Суть в одном абзаце

**Campaign — это запускаемый инстанс Flow.** Flow задаёт *путь* (граф шагов), а кампания — это конкретный запуск этого пути: она привязывает **один Flow** + **Link-домен** + **Source**, из чего генерится tracking-ссылка для рекламы. По клику на ссылку в кампании рождается визит. Всё, что дальше с этим визитом происходит (показы, фильтрация, лиды, косты, конверсии), **агрегируется обратно на кампанию** — поэтому кампания это ещё и «единица отчётности», вокруг которой крутится вся аналитика медиабаера.

## Как это работает на самом деле

### 1. Кампания = инстанс, Flow = класс

Полезная аналогия из программирования: **Flow — это класс (шаблон), Campaign — его экземпляр.** Один Flow переиспользуется десятками кампаний. Это намеренно: байер один раз собирает «правильный» путь (Source → Filter → Preland → Offer → Destination), а потом плодит под него кампании — по гео, по офферу, по крео — не пересобирая логику каждый раз.

Из этого вытекает ключевое свойство и ключевой подвох:
- **Свойство:** меняешь Flow — меняется поведение *всех* кампаний на нём (общая логика в одном месте).
- **Гоча:** **менять Flow под уже активными кампаниями нельзя** — новые шаги/лэнды к ранее созданным кампаниям не подтянутся корректно. Правильно — создать новый Flow и с него запускать новые кампании. См. [models/flow-model.md](flow-model.md).

### 2. Edit Campaign = оверлей поверх шагов Flow

Когда открываешь `Edit Campaign`, справа ты видишь **шаги привязанного Flow в виде карточек** — это и есть «инстанс» пути. Но редактируются не все настройки, а только те, что Flow разрешил трогать на уровне кампании — механика **`Settings Availability`** (`Campaign Template` / `Flow Only` / `Campaign Only`), детально — [models/flow-model.md](flow-model.md) → Settings Availability.

Поэтому два байера на одном Flow могут иметь разные лэнды/фильтр/дестинейшны в своих кампаниях — каждый правит свой оверлей, не ломая общий чертёж. Что именно правится в Edit Campaign — [how-to/campaigns.md](../how-to/campaigns.md).

### 3. Ссылка — это «адрес» кампании, `cuuid` — её идентичность

Кампания существует для трафика только через **ссылку**, которую собирает **Link Generator** из тройки `Campaign + Domain + Source`. В ссылке зашит **`cuuid` = UUID этой кампании** (и `suuid` = UUID source). По `cuuid` AIO определяет, *в какую кампанию* положить визит (агент принимает клик и передаёт параметры). Нет `cuuid`/`suuid` в ссылке → это Direct Traffic, и кампанию надо донавесить через `Default Query` домена или `Direct Traffic Distribution` (см. [mechanics/visit-lifecycle.md](../mechanics/visit-lifecycle.md)). В MTK путь прямого трафика только один — `Default Query` на каждом домене; `Direct Traffic Distribution` в MTK не используется.

Одна кампания может породить **много ссылок** (разные домены, разные Source, разные `Launcher`-ы при multi-buyer) — но `cuuid` у них один. История ссылок живёт в `Edit Campaign → Link history`.

### 4. Кампания — корень агрегации (деньги и аналитика)

Визиты, лиды, конверсии, косты — всё это «висит» на кампании, и вокруг неё крутится вся аналитика по деньгам. **Основной способ видеть косты и профит по FB — метрика `Meta Spend`** (движок `AIO Attribution Engine`): она считается на лету в момент отчёта, матчит по `FB Ad ID`, ничего не теряет и стоит рядом с revenue — профит и ROI по FB читаются прямо в отчёте по любому разрезу, стратегию костов на кампании для этого выбирать не нужно. Разбор — [mechanics/meta-spend-allocation.md](../mechanics/meta-spend-allocation.md).

Здесь же, на кампании, живёт **`Costs update strategy`** — **старый путь** заливки рекламных расходов в метрику `Costs` **на самих визитах** (для классического ROI-столбца в трекере). Оставлен как справка; по костам/профиту FB ориентируйся на `Meta Spend`, а перелив трогай, только когда нужен именно visit-level `Costs`:
- `Manual` — косты вносятся руками (`Update costs`: за период, по полю, Costs/CPC);
- `AIO Meta` / `Meta Account` / `Meta Campaign` / `Meta AdSet` — автоперелив FB-костов в метрику `Costs` с атрибуцией по соответствующему уровню FB-иерархии (`AIO Meta` = по `FB Ad ID`, самый точный уровень). В колонке `Cost Strategy` эти значения подписаны иначе: `AIO Meta` показывается как **`Meta Ad`**, `Meta AdSet` — как **`Meta Ad Set`**.

Без выбранной стратегии костов пустой останется именно visit-level `Costs` (классический ROI-столбец в трекере) — но косты и профит по FB всё равно видны через `Meta Spend`, ему стратегия не нужна. Детали перелива, AIO Meta и ретро-окна атрибуции — [how-to/campaigns.md](../how-to/campaigns.md).

### 5. Часть полей кампании AIO проставляет сам — не руками

Несколько аналитических полей кампании AIO **пересчитывает по фоновому расписанию из свежего трафика**, поэтому они появляются и меняются сами, а не вводятся вручную:

- **`quality`** — доля хорошего трафика (`good / (good + bad)` в процентах) за скользящий последний час; пересчитывается сам, поэтому число «плавает».
- **`detected_country`** — топ-страна трафика кампании за последний час.
- **`detected_source_uuid`** (аналитическая колонка `Detected source`) — источник кампании определяется сам по преобладающему трафику; это распознанный источник, не сама сущность `Source` (см. «Source vs Detected source» в [models/source.md](source.md)).
- **visit-level `Costs`** — заливаются автопереливом FB-костов, если выбрана стратегия костов (раздел выше).

Отсюда типовой вопрос «почему у меня само проставилось / когда обновится»: у этих полей есть лаг — свежий трафик отражается в них спустя несколько минут после того, как отработает соответствующий фоновой пересчёт. Список фоновых пересчётов AIO и их частота — *Что AIO проставляет и делает сам — фоновые задачи и их расписание*.

### Номер кампании (`human_id`) — 6 цифр вида `007567`

Помимо UUID у кампании есть короткий человекочитаемый номер **`human_id`** — 6 цифр с ведущими нулями, например `007567`. Именно его показывают таблицы и разбивки статистики (рядом с именем), и по нему удобно искать кампанию вместо длинного `cuuid`. Формат `#7567` = тот же номер без ведущих нулей. Номер не участвует в tracking-ссылке — в ней едет `cuuid` (UUID), а `human_id` только для человека в UI.

## Кампания в MTK — те же кнопки минус три

**В MTK-билде кампания работает так же, как в ERP, за вычетом ровно трёх вещей** (MTK — это ограниченный вид того же тенанта, разбор — *Как устроен MTK-вид AIO: навигация, пресеты из шаблона и методы под типовые задачи*):

1. **Флоу только выбрать, не собрать.** Поле `Traffic flow` в `Edit Campaign` — это дропдаун с преднастроенными флоу (приходят из шаблона тенанта). Создавать новые и редактировать существующие флоу в MTK нельзя — редактора флоу в этом виде нет. «Кампания = инстанс Flow» остаётся верным, только Flow берётся готовым.
2. **Нет `Conversions AI` / `Metrics AI`.** AI-стратегии оптимизации в MTK недоступны.
3. **Нет `LP Splits`.** Сплитить элементы внутри лэнда нельзя; ротация — только целыми лэндами через веса в блоке `Landing` кампании (`First` / `Weights`).

Всё остальное в `Edit Campaign` идентично ERP: встроенный фильтр в блоке `AIO Filter` (его параметры — *уточните у поддержки*), косты, домены, source — как обычно. Где что лежит в MTK-навигации — *Как устроен MTK-вид AIO: навигация, пресеты из шаблона и методы под типовые задачи*.

## Как Campaign связана с остальными сущностями

- **Campaign → ровно один Flow** (путь). Наследует структуру + оверрайды шагов.
- **Campaign + Source → Link → Visit.** Визит входит по `cuuid`+`suuid`.
- **Campaign → Link-домен.** Обычно трекинговый; публичный домен может подменяться шагом `Domain-Change` внутри пути ([models/domain.md](domain.md)).
- **Campaign ← Visit / Conversion / Cost.** Корень роллапа всей статистики.
- **Campaign → шаги Flow** показываются карточками в `Edit Campaign` (оверлей по `Settings Availability`).

## Чем Campaign отличается от смежных понятий

| Не путать | Разница |
|---|---|
| **Campaign vs Flow** | Flow — переиспользуемый **чертёж** пути (States+Transitions). Campaign — **один запуск**, привязывающий Flow к домену+сорсу. Один Flow → N кампаний. |
| **Campaign vs Source** | Source — пресет **происхождения** трафика (что ловить из URL). Campaign **использует** Source; трафик сама не «генерит», только определяет путь. |
| **Campaign vs Link** | Ссылка — **производное** (`Campaign + Domain + Source` → Link Generator). Одна кампания → много ссылок, один `cuuid`. |
| **Campaign vs «кабинет FB»** | В AIO кампания — это **трекерная** сущность (путь+ссылка+статистика), не рекламная кампания FB. FB-кампании живут в разделе `Meta`; привязываются для перелива костов в `Costs` (AIO Meta — старый путь; основной способ по костам/профиту FB — метрика `Meta Spend`, [mechanics/meta-spend-allocation.md](../mechanics/meta-spend-allocation.md)). |

## Подводные камни Campaign — частые ошибки настройки

- **Flow под активными кампаниями не меняем** — новый Flow для новых запусков.
- **`Copy campaign`** — штатный способ плодить варианты (то же на том же Flow, меняешь только оверлей).
- Visit-level `Costs` (классический ROI-столбец) пустой → проверь `Costs update strategy` (не `Manual` без ручного ввода; для FB — соцка подключена через `Connect`). Косты/профит по FB при этом всё равно видны через `Meta Spend` — ему стратегия не нужна.

## `Lock campaign to this domain` — привязать кампанию к одному домену

**По дефолту любой добавленный в тенант домен может открыть любую кампанию.** Toggle `Lock campaign to this domain` (в `Edit Campaign` / `Link Generator`, по дефолту выключен) это закрывает: кампания открывается только под указанным доменом. Выбор нескольких доменов не поддержан — один toggle = один домен.

Не путать с `Lock Domain` — это разные настройки:
- **`Lock campaign to this domain`** (toggle в Edit Campaign / Link Generator) — кампания открывается только под этим доменом.
- **`Lock Domain`** (в меню действий на самом домене, [models/domain.md](domain.md)) — инфраструктурный запрет на изменение и перенос самого домена.
