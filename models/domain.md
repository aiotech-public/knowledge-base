# Domain — концепт (модель)

> Модель сущности **Domain**. Процедуры (Buy/Manual, репойнт, чекеры, Replace, SSL) — [how-to/domains.md](../how-to/domains.md). Инфраструктура (агент/CDN/репойнт) — [context/architecture.md](../context/architecture.md). UI — `Tech → Domains`.

## Что такое Domain в AIO и зачем он нужен

**Domain — это доменное имя, зарегистрированное в AIO, на которое указывают tracking-ссылки и которое резолвится (через DNS-провайдера) на серверы-агенты AIO.** Домен — это «адрес» инфраструктуры кампании. У него две **роли** по жизни: **трекинговый** (тот, что зашит в рекламу) и **публичный** (под которым реально открывается лэнд после фильтрации) — AIO переключает их по ходу визита, и это by design.

## Как устроен Domain: запись, роли, инфраструктура, мониторинг

### Что хранит запись Domain и на что она указывает

Домен в AIO — не просто имя, а запись со связями (`Tech → Domains → Add manually`): **Domain** + **Servers** (на какие агенты указывает) + **DNS provider** (кто держит DNS-записи, обычно Cloudflare) + **Monitoring user** (кому алерты при падении) + тоггл **`Allow indexing by search engines`** (в модалке `Edit Domain`; для фильтр-доменов выключен) + **Direct Traffic Distribution** (выбор дистрибуции — без него или без `Default Query` голый заход без `cuuid`/`suuid` вернёт `502` и в кампанию не попадёт; см. [how-to/distributions.md](../how-to/distributions.md)). Купить можно через подключённый **Domain Provider** (регистратор), либо добавить уже свой (тогда NS надо перевести на DNS-провайдера AIO вручную).

### Трекинговый ↔ публичный Domain — зачем две роли и как переключает Domain-Change

Смысл двух ролей — развести адрес, зашитый в рекламу, и адрес, под которым реально открывается лэнд:
- **Трекинговый домен** (разг.: «тех домен», «технический домен») — тот, что в объявлении. По нему ходит вся внешняя проверка площадки, поэтому он «на виду» и попадает под ограничения первым.
- **Публичный домен** — на него уходит **реальный** визит после фильтрации. Его, кроме прошедших фильтр пользователей, снаружи не видно.
- Переключает их **шаг `Domain-Change`** внутри пути визита. При блокировке **публичного** — `Replace Domain` без перезапуска рекламы (в объявлении зашит трекинговый, его не трогаем); при блокировке **трекингового** — `Replace Domain` не спасёт (AIO в объявление не лезет), кампанию перезапускают с новой ссылкой на стороне площадки.

То есть один визит может пройти через **несколько** доменов, и это by design.

### Как Domain живёт на серверах — Repoint Group и автоматический репойнт

Домены «живут» на **серверах-агентах**, сгруппированных в **Repoint Group**. Если сервер падает (бан аккаунта провайдера, не оплатили) — **все домены, смотревшие на него, автоматически репойнтятся** на **случайный** живой сервер **в той же Repoint Group** (выбор случайный, гео/latency при выборе не учитываются — географию задаёт сама группа). Чтобы это работало — нужно ≥2 живых сервера в группе, желательно у разных провайдеров. Единственный реальный даунтайм — DNS-пропагация. См. [context/architecture.md](../context/architecture.md), [how-to/domains.md](../how-to/domains.md) → Repoint.

### Как отслеживается здоровье Domain — пинг, мониторинг и чекеры

- **Пинг** каждые 5 минут с географически распределённых агентов (несколько регионов), решение по кворуму (упал/жив) — механика и алерты в [context/architecture.md](../context/architecture.md) §Pinging.
- **Чекеры** (`Tech → Domain checkers`: Google Threat / VirusTotal) проверяют домен на «красный экран» / блек-лист. Жёлтый индикатор = suspicious от чекеров.
- DPI-блокировки делают внешние чекеры бесполезными — реальный чек только из нужной страны.

## Как Domain связан с Campaign, Server, Flow и провайдерами

- **Campaign → Link-домен** — кампания указывает на домен через ссылку.
- **Domain → Servers (Repoint Group)** — куда резолвится; репойнт при падении.
- **Domain-Change-шаг** переключает трекинговый ↔ публичный (механика — «Трекинговый ↔ публичный Domain»).
- **Domain → DNS provider** (Cloudflare) — управление записями; **Domain checkers** — мониторинг доступности.

## Что путают с Domain — трекинговый vs публичный, Server, Provider, Source

| Не путать | Разница |
|---|---|
| **Трекинговый vs публичный домен** | Трекинговый — в рекламе (на виду, попадает под ограничения первым). Публичный — куда уходит реальный визит после фильтрации. Переключает `Domain-Change`. |
| **Domain vs Server** | Domain — имя/адрес. Server (агент) — машина, на которую домен указывает ([models/server.md](server.md)). Много доменов → один сервер; репойнт меняет привязку. |
| **Domain Provider vs DNS Provider** | Domain Provider — регистратор, где домен **куплен** (Namecheap…). DNS Provider — где живут **DNS-записи** (Cloudflare). Разные роли, разные апишки. |
| **Domain vs Source** | Domain — инфраструктурный адрес. Source — пресет происхождения трафика. Не связаны напрямую. |

## Частые ошибки с Domain — что идёт не так

- **Репойнту нужен ≥2 живых сервера в группе** (лучше у разных провайдеров) — иначе переезжать некуда.
- **Блокировка трекингового vs публичного** — разные последствия; детали в «Трекинговый ↔ публичный Domain».
- **Manual-добавление без перевода NS** на DNS-провайдера AIO → AIO не управляет DNS, домен «глух».
- **`Allow indexing by search engines`** (тоггл в `Edit Domain`) для фильтр-доменов **выключен** (не SEO).
