# Domain — концепт (модель)

> Модель сущности **Domain**. Процедуры (Buy/Manual, репойнт, чекеры, Replace, SSL) — [how-to/domains.md](../how-to/domains.md). Инфраструктура (агент/CDN/репойнт) — [context/architecture.md](../context/architecture.md). UI — ERP: `Tech → Domains`, MTK: вкладка `Domains`.

## Что такое Domain в AIO и зачем он нужен

**Domain — это доменное имя, зарегистрированное в AIO, на которое указывают tracking-ссылки и которое резолвится через DNS на серверы-агенты AIO.** Домен — это «адрес» инфраструктуры кампании. У него две **роли** по жизни: **трекинговый** (тот, что зашит в рекламу) и **публичный** (под которым реально открывается лэнд) — переход между ними настраивается шагом `Domain-Change` во Flow.

## Как устроен Domain: запись, роли, инфраструктура, мониторинг

### Что хранит запись Domain и на что она указывает

Домен в AIO — не просто имя, а запись со связями (ERP: `Tech → Domains`, MTK: `Domains`; затем `+ Domain → Add manually`): **Domain** + **Servers** (на какие агенты указывает) + **DNS provider** (кто держит DNS-записи, обычно Cloudflare) + **Monitoring user** (кому алерты при падении) + тоггл **`Allow indexing by search engines`** (в модалке `Edit domain`; для фильтр-доменов выключен) + **Direct traffic distribution** (выбор дистрибуции). Для нового захода без tracking-ссылки `cuuid`/`suuid` должны подставиться через эту дистрибуцию или `Default Query`; если их нет после обеих обработок, агент вернёт `502` и визит в кампанию не попадёт. См. [how-to/distributions.md](../how-to/distributions.md). Купить можно через подключённый **Domain Provider** (регистратор), либо добавить уже свой. При использовании DNS-провайдера, подключённого в AIO, NS переводят на него вручную; DNS provider при Manual-добавлении необязателен.

### Трекинговый ↔ публичный Domain — зачем две роли и как переключает Domain-Change

Смысл двух ролей — развести адрес, зашитый в рекламу, и адрес, под которым реально открывается лэнд:
- **Трекинговый домен** (разг.: «тех домен», «технический домен») — тот, что в объявлении.
- **Публичный домен** — адрес лэнда, на который направляет настроенный путь визита; `Domain-Change` можно поставить после фильтрации.
- Переключает их настроенный **шаг `Domain-Change`**. **Публичный** адрес меняют без перезапуска рекламы: `Replace domain` заменяет Domain-payload в настройках выбранных кампаний; для `FlowOnly` правят сам Flow. Трекинговый адрес объявления это не меняет — его меняют в ссылке на стороне площадки.

То есть один визит может пройти через **несколько** доменов, и это by design.

### Как Domain живёт на серверах — Repoint Group и автоматический репойнт

При переходе сервера в `Danger` мониторинг выбирает неархивные домены того же Tenant, у которых он записан основным `server_uuid`. Для каждого домена нужен подключённый DNS-провайдер и хотя бы один **другой** неархивный сервер в статусе `Running` той же **Repoint Group**; без них домен остаётся в `Danger`. Цель выбирается случайно, без учёта гео/latency.

Для резервирования заранее держат **≥2 работающих сервера** в группе, желательно в разных аккаунтах провайдеров: падение общего аккаунта может затронуть все его серверы.

### Что происходит, если автоматический Repoint не удался

Авто-репойнт запускается при переходе сервера в `Danger`. При временных ошибках DNS-провайдера репойнт повторяется, всего до 6 попыток; при исчерпании — `All 6 repoint attempts failed: …`. Постоянная ошибка может завершить его раньше. После устранения причины репойнт запускают вручную. Переезд также зависит от обновления DNS и проверки домена; непрерывная доступность не гарантируется. Подробно — [context/architecture.md](../context/architecture.md) → «Repoint — что это и зачем» и [how-to/domains.md](../how-to/domains.md) → Repoint.

### Как отслеживается здоровье Domain — пинг, мониторинг и чекеры

- **Мониторинг доступности** — у домена с включённым мониторингом AIO сам следит, отвечает ли через него агент AIO, и заодно видит проблемы DNS, сертификата и срока регистрации (`Domain expiring: …`). Упавший домен — `Danger` со строкой причины и Telegram-отчёт `AIO Monitoring · Domains`. Механика и алерты — [context/architecture.md](../context/architecture.md) → «Мониторинг и нотификации».
- **Чекеры** (ERP: `Tech → Domain checkers`, MTK: `Settings → Domain checkers`; Google Threat / VirusTotal) проверяют домен на «красный экран» / блек-лист. Вердикт чекера кладёт домен в `Danger` со строкой `<имя чекера> Incident: <вердикт>` — отдельного «жёлтого» статуса под чекеры нет (жёлтый значок в строке домена — включённый `Under Attack`).
- DPI-блокировки делают внешние чекеры бесполезными — реальный чек только из нужной страны.

## Как Domain связан с Campaign, Server, Flow и провайдерами

- **Campaign → Link-домен** — кампания указывает на домен через ссылку.
- **Domain → Servers (Repoint Group)** — куда резолвится; репойнт при падении.
- **Domain-Change-шаг** переключает трекинговый ↔ публичный (механика — «Трекинговый ↔ публичный Domain»).
- **Domain → DNS provider** (Cloudflare) — управление записями; **Domain checkers** — проверка угроз и блек-листов.

## Что путают с Domain — трекинговый vs публичный, Server, Provider, Source

| Не путать | Разница |
|---|---|
| **Трекинговый vs публичный домен** | Трекинговый — в рекламе. Публичный — адрес лэнда. Переход на него задаётся шагом `Domain-Change` во Flow, например после фильтрации. |
| **Domain vs Server** | Domain — имя/адрес. Server (агент) — машина, на которую домен указывает ([models/server.md](server.md)). Много доменов → один сервер; репойнт меняет привязку. |
| **Domain Provider vs DNS Provider** | Domain Provider — регистратор, где домен **куплен** (Namecheap…). DNS Provider — где живут **DNS-записи** (Cloudflare). Разные роли, разные апишки. |
| **Domain vs Source** | Domain — инфраструктурный адрес. Source — пресет происхождения трафика. Не связаны напрямую. |

## Частые ошибки с Domain — что идёт не так

- **Для резерва заранее держат ≥2 работающих сервера в группе**, лучше в разных аккаунтах провайдеров. После падения нужен хотя бы один другой `Running` сервер; условия выборки доменов — в разделе про автоматический Repoint.
- **Блокировка трекингового vs публичного** — разные последствия; детали в «Трекинговый ↔ публичный Domain».
- **При Manual-добавлении с DNS-провайдером AIO** NS переводят на выбранного провайдера. Без подключённого DNS-провайдера записи поддерживают вручную; автоматический репойнт AIO для такого домена недоступен.
- **`Allow indexing by search engines`** (тоггл в `Edit domain`) для фильтр-доменов **выключен** (не SEO).
