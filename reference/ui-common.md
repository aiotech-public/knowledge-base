# Общий UI таблиц и экшенов AIO

Почти каждый раздел AIO (Campaigns, Sources, Destinations, Flows, Trackers, и т.д.) — это **таблица сущностей** с одинаковым тулбаром, системой `Presets` и набором повторяющихся right-click экшенов. Здесь они описаны **один раз**; разделы ссылаются сюда и документируют только своё уникальное.

---

## Что есть в тулбаре таблицы AIO и за что отвечает каждая кнопка

- **`+ <Сущность>`** (зелёная) — создать (рядом дропдаун с вариантами создания, где есть).
- **Tags / Text** + **поиск** «by uuid or name».
- **Traffic** — **тоггл** «Hide empty columns / показывать только строки с трафиком» (добавляет `hideEmptyMetrics` в URL). Включён → сущности **без трафика скрыты** (частая причина «не вижу кампанию/источник»).
- **`N of M`** (напр. «0 of 2», правее Traffic) — **кликабельный** дропдаун display-опций таблицы:
  - **`Archived`** — показывать архивные сущности. В части разделов этот тоггл подписан **`With Archived?`** (напр. DNS Providers, Landings, Servers, Conversions) — это то же самое: показать/скрыть архивные сущности. Когда архивные показаны (тоггл включён), их **имена в таблице зачёркнуты**.
  - **`Attribute by events time`** — атрибуция метрик по **времени событий** (конверсий), а не по времени визита.

  Само число `N of M` — счётчик сущностей в выборке.
- **Фильтры-дропдауны** (мульти-селект, поиск, -избранное) — зависят от раздела: `Geo` (страна), `Owner` (владелец), `Team` (команда), `Advertiser types`, `Advertisers`, `Flow type`…
- **Иконки графика/колонок** (рядом с `Presets`) — быстрые виды.
- **Date-range** (справа): `Last month / Last week / Yesterday / Today / This week / This month` + календарь — фильтрует метрики таблицы.
- **View toggle** — таблица / грид; **folder** (папки, только ERP), **refresh**, **пагинация**.
- **Вторая строка:** селектор активного **пресета** (напр. «Campaigns #1») + `+` (новый пресет).

### Почему в ячейках метрик пропали мини-графики (спарклайны)

Спарклайн — мини-график тренда прямо в ячейке метрики таблицы. Он строится только на коротком периоде: если в date-range выбран диапазон **в 31 день и больше**, спарклайны не рисуются — в ячейках остаются одни числа. Это штатное поведение, а не сбой: «поставил месяц — графики в ячейках исчезли» лечится сужением периода.

Спарклайнов также нет там, где таблица отдаёт данные не в интерфейс: в выгрузке по API-токену ([how-to/api.md](../how-to/api.md)) и в таблицах, которые собирает по запросу AI-чат ([how-to/ai-chat.md](../how-to/ai-chat.md)) — там приходят только значения метрик.

## Как настроить колонки, фильтры и пресеты таблицы через Presets → Table settings

Кнопка **`Presets`** → пункт **`Table settings`** открывает универсальную настройку таблицы:

- **Пресеты** — именованные сохранённые конфиги (колонки + фильтры + page-size). Сверху селектор пресета + `+`. Внизу: имя в `Enter preset name` (левый нижний угол) + **Save** (сохранить как пресет), **Reset settings**, **Apply**. При правке существующего пресета его можно перезаписать или сохранить под новым именем тогглом `Save as New`.
- **Page size** — число сущностей на страницу: `10 / 25 / 50 / 100`.
- **Filters** (слева) — по каким полям фильтровать. Группы **Regular** (поля сущности: UUID, Tags, Geo, …) и **Analytics** (метрики); фильтр можно вынести в избранное. Тогглы `Archived` / `Migrated`.
- **Columns** (справа) — какие колонки показывать (чекбоксы), `Reorder columns` (drag-and-drop порядка колонок), поиск по колонкам. Группы **Regular** (поля сущности) и **Analytics** (метрики: `Qualified visits`, `Leads`, `Registrations`, `Purchases`, …).
- **Groupers** — здесь же можно **применить или найти (search) групперы** для таблицы и пометить записи как **Favorites**. Групперы строят отчёты — см. [how-to/analytics.md](../how-to/analytics.md).

То есть «какие колонки и фильтры видно в таблице» настраивается здесь и сохраняется пресетом. У каждого раздела — свой набор колонок Regular/Analytics.

Пресеты применимы к таблицам Campaigns, Landing Pages, Destinations, Sources, Visits, Conversions, Domains и др.

### Как создать пресет централизованно через Settings → Presets

Помимо `Table settings`, пресет можно создать через `Settings → Presets → +Preset`: задать `Preset Name`, `Type` (вид пресета — см. ниже), тоггл `Is Default?` (делает пресет дефолтным для всех юзеров) и код пресета → `Confirm`. Любой пресет (созданный любым способом) попадает в таблицу `Settings → Presets` и в дропдаун `Presets` на таблице. Пресеты есть и в ERP, и в MTK.

Поле `Type` пресета — это не только «для какой сущности таблица». Список включает **40 значений** двух групп:

- **Отчётно-аналитические** — пресет для отчёта/дашборда, а не для таблицы сущностей: `DD Report`, `Cohort Report`, `Compare Analytics`, `Dashboard`, `Charts Builder`, `Data Exporter`.
- **Табличные (по сущностям)** — конфиг колонок/фильтров таблицы конкретной сущности: `Table Campaigns`, `Table Sources`, `Table Destinations`, `Table Visits`, `Table Conversions`, `Table Landings`, `Table Advertisers` и т.д., включая `Table Roadmap Tasks` и `Table Other`.

## Что такое Tags и как они помогают искать и сортировать сущности в AIO

`Tags` — кастомизируемые метки для быстрого поиска и сортировки сущностей (Campaign, Destination, Landing, Flow, страна, язык и т.д.). Поле `Type` тега определяет, что тег матчит:

- **`Country`** — страновой тег (значение из списка стран); используется для странового матчинга.
- **`Language`** — языковой тег; используется для языкового матчинга.
- **`String`** — произвольный текст; просто метка, без странового/языкового матчинга.

Сам тег заводится полями `Name` + `Color` + `Type`. Взаимоисключающих тегов нет: у сущности может быть сколько угодно тегов или ни одного. Цвет тега — только для удобства (быстрее найти в таблице), на логику матчинга он не влияет.

### Как создать и добавить Tag к сущности

- У сущностей с кнопкой `Tags` рядом с поиском (Campaign, Destination, Flow, Landing, Macros, Server, Domain, DNS Provider, Domain Provider, Server Provider) тег создаётся синей кнопкой `Tags` → `Create new tag`: задать `Name`, `Color`, `Type` (`String` / `Country` / `Language`) и группу.
- У остальных сущностей теги добавляются в их Edit-окне — поле `Tags` (Edit-окна Campaign / Flow / Landing выглядят иначе, чем у прочих).

### Что такое Tag Groups и как группировать теги через Settings → Tags

`Tag Groups` группируют существующие теги для удобства. Группы и сами теги создаются в `Settings → Tags`: дропдаун → `Manage Tag Group` → `+Tag Group`, далее `Group Name`, `Description`, `Type` (тот же набор `String` / `Country` / `Language`, что у тега) и набор тегов в группе.

## Какие right-click экшены доступны на любой сущности AIO

Повторяются на большинстве сущностей (точный состав чуть разнится по разделу):

| Экшен | Что делает |
|---|---|
| **Edit <сущность>** | редактор сущности |
| **Copy <сущность>** | дубль |
| **<сущность> logs** | логи сущности |
| **Assign color** / **Assign to folder** (Assign to folder — только ERP) | цвет / папка для группировки в таблице |
| **Show visits / conversions / sessions** | перейти к визитам / конверсиям / сессиям, отфильтрованным по этой сущности |
| **Build Roll Up report** | открывает `Analytics → Roll Up report` (`/analytics/dd`), **пред-отфильтрованный** по этой сущности — дальше строишь отчёт групперами (см. [how-to/analytics.md](../how-to/analytics.md)) |
| **Share** | выдать доступ (см. ниже) |
| **Change ownership** / **Change owner** | сменить владельца сущности |
| **Archive** / **Switch archive** | в архив / из архива |
| **Highlight row** | подсветить строку |
| **Freeze top / bottom** | закрепить строку сверху/снизу |

### Как выдать доступ на объект через Share

Модалка `Share`:
- **Слева «Users in tenant»** — кого добавить: вкладки **All / Users / Teams**. Можно дать доступ отдельным пользователям или целым командам (Teams); кнопка `Add all`.
- **Справа «Users»** — у кого уже есть доступ: у каждого права (просмотр / редактирование) + убрать. Тоггл **«Everyone can edit»** (дать всем право редактирования), `Remove all`.

Это **объектный** шеринг (на уровне конкретной сущности). Ролевые права тенанта в целом — `Settings → Positions / Teams` (см. [models/permissions-model.md](../models/permissions-model.md)).
