# Свой макрос в AIO — как написать, подключить и проверить

## Что такое макрос в AIO — свой скрипт или пиксель на всех лэндах сразу

**Макрос — кусок HTML (обычно `<script>`), который AIO вставляет в лэнд при каждой отдаче страницы визиту; код выполняется в браузере посетителя рядом с AIO SDK.** Макросы лежат в `Content → Macros` (в MTK — `Settings → Macros`). Так подключают свой скрипт, пиксель партнёрки или рекламной сети, счётчик, правку SDK-формы — один раз на все лэнды вместо копирования кода в каждый архив.

На страницу макрос попадает одним из двух способов. Глобальный (`Global?` включён) AIO ставит сам на каждый лэнд, у типа которого включён `Auto place AIO macros?` (колонка `AIO Macros` в списке типов). Локальный встаёт только туда, где в HTML лэнда написан вызов `{{aio:macros:<slug>}}`.

Чего макрос не делает:

- не выполняется на сервере: PHP-вставки вроде `<?=$_GET['x']?>` не работают, значения визита подставляют плейсхолдерами `{{aio.visit.fields.<slug>}}` ([reference/placeholders.md](../reference/placeholders.md));
- не создаёт своих плейсхолдеров: текстовой переменной вида `{{funnel}}` из макроса не получится, текст на страницу выводит только его JS;
- не грузится по условию: правил «ставить макрос, только если…» нет, условие пишут `if` внутри кода.

Шаблонные макросы, которые приезжают с тенантом (`AIO SDK Macros Collection`, `AIO GTAG`, `AIO Non-SDK Form Handler` и другие), описаны в [reference/sdk.md](../reference/sdk.md).

## Как создать макрос — `Content → Macros` → `+ Macros`

**Макрос создают кнопкой `+ Macros` в `Content → Macros` (в MTK — `Settings → Macros`); откроется диалог `Create macros`.** Поля:

1. `Name` — только латиница, цифры, пробел и знаки `` - _ ' ` . : ``, до 255 символов; имя на кириллице не сохранится. Из имени строится slug (раздел «Какой slug получит макрос»).
2. `Description` — до 255 символов; `Tags` — для фильтра в таблице.
3. `Prefer placement` — `Footer` (по умолчанию) или `Head`; что это меняет — раздел «Head или Footer».
4. `Active?` — включён ли макрос, по умолчанию включён.
5. `Global?` — **по умолчанию включён**: сохранённый макрос начинает вставляться на все лэнды. Нужен не везде — выключите до сохранения.
6. `Html` — код целиком, с тегами `<script>…</script>`, `<style>` или разметкой. AIO вставляет содержимое поля в страницу как есть: без обёртки, проверки и минификации.

Правка — правый клик по строке → `Edit macros`, поля те же. Раздел видят с правом `Content: macros page` (`content.macros.view`), создают и правят с `Content: macros edit` (`content.macros.edit`), архивируют с `Content: macros archive` ([models/permissions-model.md](../models/permissions-model.md)).

### Какой slug получит макрос и можно ли его поменять

**Slug строится из `Name` один раз, при создании: имя в нижнем регистре, пробелы заменяются на `_`, всё, кроме латинских букв, цифр и `_`, удаляется.** Имя `My Pixel v.2` даёт slug `my_pixel_v2`. Если такой slug в тенанте уже занят (в том числе макросом в архиве), добавляется числовой суффикс: `my_pixel_v2_1`, затем `my_pixel_v2_2`.

Поменять slug нельзя: поля для него в форме нет, а переименование макроса slug не пересчитывает. После смены `Name` работает старый вызов `{{aio:macros:<старый slug>}}`, а вызов, собранный «по новому имени», — нет. Точный slug — в колонке `Slug` таблицы `Content → Macros` и в подсказке у значка `#` в колонке `Macros`: `Inserted only by slug: <slug>`.

## Global или `{{aio:macros:<slug>}}` — макрос на все лэнды или только на выбранные

**Глобальный макрос AIO ставит сам на каждый лэнд, у типа которого включён `Auto place AIO macros?`; локальный (`Global?` выключен) — только туда, где в HTML лэнда написан вызов `{{aio:macros:<slug>}}`.**

- Исключить из глобального макроса один лэнд нельзя. Нужен не на всех — сделайте макрос локальным и вставьте вызов в нужные лэнды.
- Вызов пишется строго `{{aio:macros:my_pixel}}`, без пробелов внутри скобок: `{{ aio:macros:my_pixel }}` не распознаётся и уходит на страницу текстом.
- Локальный макрос встаёт ровно на место вызова, `Prefer placement` для него не действует. Нужен в `<head>` — пишите вызов внутри `<head>`. Каждое вхождение вызова даёт отдельную копию кода.
- Вызов глобального макроса в HTML лэнда вырезается: глобальный и так стоит на странице, второй раз он не вставляется.
- Вызов, для которого нет активного макроса с таким slug (нет в тенанте, выключен, в архиве), вырезается из HTML без ошибки.
- Локальный вызов, как и глобальный макрос, работает только на лэндах типа с включённым `Auto place AIO macros?`: на остальных AIO вырезает со страницы все макросы.
- Вызов внутри кода другого макроса ненадёжен: из глобального макроса он не раскрывается вовсе, из локального — только при удачном порядке вставки. Вкладывать макросы друг в друга не нужно.

## Head или Footer — куда AIO вставит код глобального макроса

**`Prefer placement` = `Head` ставит глобальный макрос в плейсхолдер `{{aio:head}}` в конце `<head>`, `Footer` — в `{{aio}}` перед `</body>`.** Если `{{aio:head}}` на странице нет, `Head`-макросы тоже уходят в `{{aio}}`; об этом и подсказка поля: «Where to put macros if corresponded placeholder exists».

- Оба плейсхолдера AIO дописывает сам при загрузке ZIP, если у типа лэнда включён `Auto place AIO macros?`. В лэнд из `Create manually` их не вставляет — они должны быть в коде ([how-to/landings.md](landings.md)).
- Перед макросами AIO ставит скрипт с объектом визита `window.aio` и очередью команд `window.aioBus`: в `{{aio:head}}`, если он есть на странице, иначе первым в `{{aio}}`.
- Порядок нескольких глобальных макросов между собой не задан и может меняться. Код не должен рассчитывать на то, что стоит после другого макроса.
- `Head` выбирают для того, что должно сработать до отрисовки страницы: часть пикселей, A/B-тест до показа контента, `<meta>`-теги. Когда выполняется такой код, `<body>` ещё не разобран, поэтому к элементам страницы обращаются после события `DOMContentLoaded`.

## Что уже есть на странице, когда выполняется код макроса — `window.aio`, `aioBus` и SDK

**К моменту выполнения кода макроса объект визита `window.aio` и очередь `window.aioBus` уже есть (если макрос стоит после них), а SDK ещё не стартовал: он запускается по `DOMContentLoaded`.** Бандл SDK подключает глобальный макрос `AIO SDK Macros Collection`, поэтому свой глобальный макрос может оказаться на странице и до, и после него.

- Команды SDK не вызывают напрямую — их кладут в очередь: `window.aioBus = window.aioBus || []; window.aioBus.push({...})`. На старте SDK разбирает очередь в порядке добавления, а более поздние команды подхватывает дальше: очередь перечитывается каждые 50 мс.
- Событий у SDK нет, в том числе «SDK готов» и «форма отрисована». Команда `dom-ready` (`window.aioBus.push({type: 'dom-ready', fn: function () { … }})`) вызывает функцию на старте SDK — до включения фич и до отрисовки SDK-формы.
- Нужна разметка лэнда — подписывайтесь на `DOMContentLoaded`. Нужна реакция на сабмит SDK-формы — хуки формы ([reference/sdk.md](../reference/sdk.md), «Хуки формы»).
- Локальный макрос, вызванный выше места, где стоит `window.aio`, выполняется раньше объекта: обращение к `window.aio.visit` падает с ошибкой `Cannot read properties of undefined (reading 'visit')`. Ставьте вызов после `{{aio}}` или читайте `window.aio` после `DOMContentLoaded`.

## Как прочитать данные визита в макросе — плейсхолдер `{{aio.visit.*}}` или объект `window.aio`

**Данные визита макрос получает двумя путями: плейсхолдеры прямо в коде (`'{{aio.visit.fields.my_pixel_id}}'`) AIO раскрывает на сервере при отдаче страницы, а объект `window.aio` читается из JS уже в браузере.**

В коде макроса раскрываются те же плейсхолдеры, что в HTML лэнда: `{{aio.visit.*}}`, `{{aio.visit.fields.<slug>}}`, `{{aio.visit.query.<key>}}`, `{{aio.campaign.*}}`, `{{aio.source.*}}`, `{{aio.common.*}}`, `{{settings.<key>}}`, `{{aio.landing.uuid}}`, `{{link}}`, `{{form}}`. `{{cdn}}` в макросе не раскрывается: он работает только при загрузке ZIP. Без модификатора значение проходит чистку `default`: из него убираются кавычки, табуляции, переводы строк и обратный слэш. Плейсхолдер с ключом, которого нет, остаётся текстом `{{…}}` — проверяйте это в коде. Ключи и модификаторы — [reference/placeholders.md](../reference/placeholders.md).

`window.aio` — снимок визита на момент отдачи страницы: `window.aio.visit` (`uuid`, `country_code`, `language_code` и другие ключи визита), `window.aio.visit.fields.<slug>`, `window.aio.landing`, `window.aio.campaign`, `window.aio.source`. Значения в `visit`, `visit.fields`, `campaign` и `source` — строки, пустое числовое поле приходит как `"0"`; `landing.countries` и `landing.languages` — массивы. Объект не обновляется: после `trigger` в нём остаётся старое значение, а присваивание `window.aio.visit.fields.x = 'y'` в визит ничего не пишет. Полная структура — [reference/sdk.md](../reference/sdk.md), «Объект `window.aio`».

### Поле есть, а в `window.aio.visit.fields` его нет — включите `Is macros visible?`

**В `window.aio.visit.fields` попадают только поля с включённым атрибутом `Is macros visible?`, а у нового поля он по умолчанию выключен.** Симптом: `window.aio.visit.fields.my_field` — `undefined`, хотя у визита значение есть.

Варианты: включить `Is macros visible?` в карточке поля ([how-to/custom-fields.md](custom-fields.md)) или читать значение плейсхолдером `'{{aio.visit.fields.my_field}}'` — серверная подстановка от этого атрибута не зависит.

Значения, которые посетителю видеть незачем, держите в полях с выключенным `Is macros visible?` и не выводите плейсхолдером в код: всё, что попало в `window.aio` или в код макроса, видно в исходнике страницы.

## Как записать значение в поле визита из макроса — команда `trigger`

**Значение пишет команда `window.aioBus.push({type: 'trigger', key: '<slug поля>', value: '<значение>'})`; SDK копит такие значения и отправляет пачкой раз в 10 секунд и при уходе со страницы.**

```html
<script>
  window.aioBus = window.aioBus || [];
  window.aioBus.push({type: 'trigger', key: 'quiz_answer', value: 'option_b'});
</script>
```

- Поле со slug из `key` должно быть заведено в тенанте; значение для несуществующего slug молча отбрасывается.
- Пустое значение не пишется, поэтому очистить поле через `trigger` нельзя. Передавайте значение строкой: `'0'`, `'false'` — числом `0` и булевым `false` SDK может не отправить вовсе. Объект уходит строкой `[object Object]`, массив — несколькими значениями (для registry-поля).
- Два `trigger` с одним ключом между отправками — в визит уйдёт последнее значение.
- Визиту с пометкой trash значения не пишутся.
- Значение одинаковое для всех визитов лэнда (метка лэнда, имя оффера) — скрипт не нужен: его задают в `User fields` карточки лэнда ([how-to/user-fields.md](user-fields.md)).

Тайминги отправки и ответы приёмника — [reference/sdk.md](../reference/sdk.md), «Exchange: поля визита и конверсии».

### Значение из макроса не дошло до оффера — `trigger` уходит с задержкой до 10 секунд

**`trigger` отправляется не сразу: если посетитель перешёл на оффер до отправки, URL дестинейшена собирается без этого значения.** Симптом — поле у визита со временем заполнилось, а в ссылку оффера (`{{aio.visit.fields.<slug>}}`) ушло пустым.

Значение, нужное в момент перехода, передают вместе с самим переходом:

- параметром ссылки перехода: `{{link}}&quiz_answer=option_b`. Параметр со slug поля тенанта записывается в поле в том же запросе, до сборки URL дестинейшена ([reference/placeholders.md](../reference/placeholders.md), «Как вести переходы по флоу через `{{link}}`»);
- полем формы: значения сабмита пишутся в визит в запросе сабмита ([how-to/forms.md](forms.md)).

Если значение вычисляется из данных визита, а не из действий посетителя, его надёжнее записать на сервере — шагом `Fill Fields` или дистрибуцией `Fill Field` перед дестинейшеном ([models/distributions-model.md](../models/distributions-model.md)).

## Как отправить конверсию из макроса — команда `conversion`

**Конверсию отправляет команда `window.aioBus.push({type: 'conversion', type_uuid: '<UUID или slug типа конверсии>'})`; SDK шлёт её сразу, не дожидаясь пачки полей.** Необязательный `query` — параметры конверсии, те же, что у постбэка: `query: {revenue: 10}`.

- Команда уходит, только если на странице есть `window.aio` — лэнд с `{{aio}}` и типом, у которого включён `Auto place AIO macros?`.
- `type_uuid`, не совпавший ни с UUID, ни со slug типа конверсии в тенанте, конверсию не создаёт — без ошибки на странице. UUID и slug типа показывает генератор постбэка ([how-to/postback-generator.md](postback-generator.md)).
- Повторов SDK не отсекает: каждый `push` — отдельный запрос. Сколько конверсий одного типа примет визит, решает `Uniqueness Strategy` типа ([models/conversion-model.md](../models/conversion-model.md)); от повторного вызова в своём коде защищайтесь флагом.

Пример на событии `appinstalled` и разбор «конверсия не пришла или задвоилась» — [reference/sdk.md](../reference/sdk.md), «Как отправить конверсию со своего скрипта».

## Как поменять настройки SDK или SDK-формы из своего макроса — команда `config`

**Свой макрос меняет настройки SDK командой `window.aioBus.push({type: 'config', config: {...}})`; SDK сливает её с конфигом из `AIO SDK Macros Collection`, а не заменяет его.**

- Передавайте только ключи, которые меняете. Объекты сливаются по ключам; при совпадении выигрывает команда, добавленная в очередь позже.
- Массивы сливаются по номеру элемента: `form.controls: [a, b]` сольётся с первыми двумя контролами по ключам — ключи старого контрола, которых нет в новом (`rules`, `label`), останутся, как и контролы после второго. Набор контролов целиком задаёт команда `form-controls`.
- Фичи (`features.*`) SDK включает один раз, на старте. Команда, добавленная после старта SDK, фичу уже не включит и не выключит.
- Порядок глобальных макросов не задан, поэтому ключи, которые задаёт `AIO SDK Macros Collection`, для всех лэндов меняют в самой Collection. На одном лэнде их перебивает скрипт или локальный макрос, стоящий после `{{aio}}`: его команда попадает в очередь позже.
- Событие лида для своего пикселя — команда `form-submit-fn`. Её `fn` SDK вызывает на успешном сабмите SDK-формы, и она обязана вернуть функцию: `fn: function () { return function () { … }; }`. Возвращённая функция не должна бросать исключений. Иначе посетитель увидит сообщение об ошибке формы, хотя лид уже ушёл.

Ключи конфига, хуки и колбэки формы — [reference/sdk.md](../reference/sdk.md).

## Пример: свой пиксель партнёрки отдельным макросом

**Свой пиксель держат отдельным макросом, а не правкой `AIO SDK Macros Collection`: ошибка в нём не задевает форму и Backfix, а сам пиксель включается и выключается тумблером `Active?`.** Ниже — макрос с `Prefer placement` = `Head`; ID пикселя берётся из поля визита `my_pixel_id`, которое заполняет ссылка источника.

```html
<script>
(function () {
  if (window.__myPixelLoaded) return;
  window.__myPixelLoaded = true;
  try {
    var pixelId = '{{aio.visit.fields.my_pixel_id}}';
    if (!pixelId || /\{\{/.test(pixelId)) return;
    var s = document.createElement('script');
    s.async = true;
    s.src = 'https://pixel.example.com/p.js?id=' + encodeURIComponent(pixelId);
    document.head.appendChild(s);
    window.aioBus = window.aioBus || [];
    window.aioBus.push({
      type: 'form-submit-fn',
      fn: function () { return function () { try { /* событие Lead пикселя */ } catch (e) {} }; }
    });
  } catch (e) {}
})();
</script>
```

Что здесь важно: флаг `__myPixelLoaded` не даёт коду сработать дважды; проверка `/\{\{/` ловит нераскрытый плейсхолдер (поля с таким slug нет); весь код в `try`, поэтому ошибка пикселя не ломает страницу; событие лида идёт через `form-submit-fn`, только на успешном сабмите. Поле `my_pixel_id` здесь строкового формата: пустое даёт пустую строку, и пиксель не грузится; у числового поля пустое значение приходит как `"0"` — его тоже нужно отсечь.

## Как проверить, что макрос сработал

**Макрос проверяют на лэнде, открытом по ссылке кампании: превью лэнда в AIO показывает страницу без макросов.**

1. Откройте лэнд по ссылке кампании.
2. `View Source` (`Ctrl+U`): найдите код макроса — плейсхолдеры в нём уже раскрыты.
3. DevTools → Console: ошибки своего кода; ошибки SDK приходят с текстом `processAioBus error` или `<имя фичи> macros err:`. В консоли можно вывести `window.aio` и `window.aioBus`: у разобранных команд очереди стоит `catched: true`.
4. DevTools → Network: `trigger` уходит запросом `POST /api/v1/trigger/field/<visit_uuid>/` (раз в 10 секунд и при уходе со страницы), `conversion` — сразу, `POST /api/v1/trigger/conversion/<visit_uuid>/<тип>/`. Чтобы видеть в консоли каждую пачку полей, временно добавьте `window.aioBus.push({type: 'config', config: {aioExchange: {log: true}}})`.
5. Карточка визита: записанные значения появляются в полях с небольшой задержкой.

Правка макроса доходит до лэндов примерно за минуту. Перезаливать лэнд не нужно: макрос вставляется при каждой отдаче страницы.

## Как вернуть прежний код макроса — истории версий нет, есть `Macros logs` и архив

**Версий у макроса нет: сохранение перезаписывает поле `Html`.** Прежний код достают из журнала: правый клик по макросу → `Macros logs` (пункт виден с правом на логи `settings.logs.view`) открывает журнал `Settings → Logs`, отфильтрованный по этому макросу; в тексте записи о правке (`Message`) лежат переданные параметры, включая `html`. Колонка `Message` защищена: при включённой 2FA-защите данных она открывается после подтверждения кода (`Unsecured Mode`, [models/permissions-model.md](../models/permissions-model.md)).

`Archive` убирает макрос со страниц и одновременно выключает `Active?`. `Unarchive` возвращает макрос в список, но `Active?` остаётся выключенным — включите его вручную. Архивные макросы видны в таблице через фильтр `Archived`. Удаления и копирования макроса в меню нет: копию заводят через `+ Macros`, вставив код в `Html`.
