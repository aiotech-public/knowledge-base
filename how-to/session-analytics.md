# Session Analytics — записи сессий и сравнение карт лэндов

`Session Analytics` — страница раздела `Analytics`, где записи сессий и карты поведения (scroll-карта и карта кликов, она же heatmap / тепловая карта) открываются сразу по всем лэндам, а не по одному лэнду из его карточки. Две вкладки: `Session viewer` (посмотреть конкретную запись) и `Map comparison` (положить карты нескольких лэндов рядом).

## Где в интерфейсе лежит Session Analytics и кому она видна

Путь — `Analytics → Session Analytics`, роут `/app/analytics/session-analytics`, пункт меню называется `Session Analytics`. Страница объявлена только для билда **ERP**; в MTK её нет.

Доступ управляется правом **`analytics.session-analytics`** (в матрице Positions строка называется **`Analytics: sessions`**) — без него пункта в меню не будет.

Это первый **общий** вход в поведенческую аналитику. Раньше карты и записи открывались только из карточки конкретного объекта — лэнда (`Manage landing → Heatmap` / `Show sessions`), кампании или визита; эти входы остались, их разбор — [how-to/landings.md](landings.md).

В топ-баре страницы стоит переключатель из двух кнопок: **`Session viewer`** и **`Map comparison`**. Он же определяет, что показывает остальной топ-бар — фильтры просмотрщика или настройки карт.

## Session viewer — как посмотреть запись сессии

Вкладка `Session viewer` — двухпанельный экран: слева список сессий карточками, справа плеер записи выбранной сессии.

Чем управляем из топ-бара:

- **Фильтры** — `Source`, `Campaign`, `Landing` (у поля `Landing` есть кнопка полноэкранного выбора лэнда).
- **Дейт-пикер** — по умолчанию `today`.
- **Постраничная навигация** — по **24** сессии на страницу, плюс кнопка обновления списка.

Список идёт через штатный табличный API, поэтому наследует скоуп тенанта и скоуп баера по кампаниям и источникам: байер видит записи только своих кампаний и источников. **Поиска по UUID на самой странице нет** — конкретный визит быстрее открыть из его карточки через `Show sessions` ([mechanics/visit-lifecycle.md](../mechanics/visit-lifecycle.md)).

Сами записи снимает SDK на лэнде, а не агент: если у лэнда не включены соответствующие макросы (`sessionRecords` для записей, `scrolling` для карт), список будет пустым — см. [how-to/landings.md](landings.md).

## Что показывает карточка сессии в списке

Карточка сессии в левом списке несёт: иконку девайса, `Source`, бейдж **`online`**, длительность и «сколько времени назад» сессия была, плюс `Campaign` и `Landing`, если они известны.

- **`online`** — бейдж стоит, пока последнее событие сессии не старше минуты, то есть визит прямо сейчас на странице.
- **`Processing`** — подпись стоит вместо длительности, пока длительность сессии нулевая.

## Плеер записи: скорость, `Skip idle`, `Action log`

Плеер справа проигрывает запись выбранной сессии: play/pause, таймкод, набор скоростей воспроизведения и тумблер **`Skip idle`** — пропускать неактивные участки.

Под записью идёт дорожка с **метками-сигналами** (важные моменты сессии), рядом — панель **`Action log`**.

## Какие сигналы отмечены на записи сессии

На дорожке и в `Action log` проставляются сигналы:

- **начало взаимодействия** — первый скролл, клик, ввод или тач;

- **клик**;

- **вехи глубины скролла** — `5 / 10 / 25 / 50 / 75 / 100 %`;

- **первый focus в поле** формы;

- **rage-клик** — 3 клика за 1200 мс;

- **конверсия** — с типом конверсии и ревенью.

Других типов сигналов на записи нет.

## Какие данные несёт сессия: колонки таблицы сессий

За списком сессий стоит табличный набор со следующими колонками: `Visit UUID`, `Online`, `Duration`, `Events`, `Clicks`, `Scroll %`, `Source`, `Campaign`, `Landing`, `Country`, `Device`, `OS`, `Browser`, `Viewport`, `Conversion`, `Valuable`, `Trash`, `Created`.

По умолчанию скрыты: `Inside PWA?`, `Intent Avail`, `Install Avail`, `Webview`, `Useragent`.

### Чем `Valuable` отличается от `Conversion`

`Valuable` = у визита есть конверсия с `revenue > 0`. `Conversion` — отдельная колонка и отдельный факт: конверсия по визиту создана.

Отсюда частая путаница «конверсия есть, а `Valuable` пустой»: конверсия с нулевым `revenue` даёт `Conversion = да` и `Valuable = нет`. Когда нужны сессии, реально принёсшие деньги, смотреть надо на `Valuable`.

## Map comparison — сравнить карты нескольких лэндов рядом

Вкладка `Map comparison` кладёт карты нескольких лэндов бок о бок, в одинаковом режиме и масштабе.

Кнопка **`+ Landing`** в топ-баре открывает полноэкранный выбор лэнда. Одновременно держится не больше **3** панелей: при добавлении четвёртой самая ранняя выпадает. Крестик на панели убирает её вручную.

### Тип карты, устройство и слайдеры панели

Тип карты переключается в топ-баре двумя кнопками: **`Scroll map`** (глубина скролла) и **`Clicks`** (карта кликов). Рядом — 4-позиционный переключатель устройства `Scale` (Mobile / Tablet / Laptop / Desktop), по умолчанию Mobile; он общий для всех панелей.

Слайдеры **`Point size`** и **`Intensity`** — свои у каждой панели и показываются **только в режиме `Clicks`**.

Мини-сводка панели показывает `avg scroll` плюс одно из двух: `sessions` (в режиме `Scroll map`) или `clicks` (в режиме `Clicks`).

### Таблица `Read depth · Δ vs base (panel 1)` — где дочитывают дальше

Под панелями строится таблица **`Read depth · Δ vs base (panel 1)`** — насколько глубже или мельче дочитывают остальные лэнды по сравнению с первой панелью. Она появляется **только в режиме `Scroll map` и только при двух и более панелях**.

Строки таблицы — вехи глубины `25 / 50 / 75 / 100 %`. Колонка **`1 · base`** — процент дочитавших у первой панели (она и есть база). В остальных колонках стоит процент этой панели, а под ним — отклонение к базе.

### Бегунок дочитанности и синхронизация панелей

Бегунок глубины и вертикальный скролл **синхронизированы между панелями**: тянешь в одной — двигаются все, поэтому сравниваешь один и тот же экран лэнда.

Сам бегунок дочитанности на scroll-карте (при наведении показывает плашку «процент глубины / сколько сессий долистало / из скольких») — общий для всех мест, где показывается scroll-карта: вкладка `Heatmap` у лэнда, Quick Preview и панели сравнения. Разбор бегунка — [how-to/landings.md](landings.md).

## За какой период Session Analytics показывает данные

Карты и сводки строятся максимум за последние **7 суток**: если в дейт-пикере выбран более ранний период, нижняя граница молча подтягивается к этому порогу.

Список сессий в `Session viewer` отсекается более широким порогом — **14 суток**.

Просмотр уже открытой конкретной записи окном не ограничен.

## Почему в картах не различаются варианты сплита и MVT

Карты и сводка строятся **по лэнду целиком** — варианты MVT и Content Splits внутри одного лэнда в них не разделяются. Симптом: сравниваешь варианты сплита и видишь одинаковую карту на всех.

«Версия» лэнда на этой странице — это **отдельный лэнд-копия**: лэнды группируются по линии копирования, подпись версии = имя лэнда, у безымянного — `Оригинал`. Группировка нужна только для подписей панелей; сам лэнд для панели выбирается обычной таблицей выбора.

Как сравнить варианты по heatmap: завести их отдельными лэндами-копиями (`Content → Landings → ПКМ → Make version`, см. [how-to/landings.md](landings.md)) и сравнить эти лэнды. Сравнивать в `Map comparison` можно любые лэнды — из одной линии копирования они быть не обязаны.
