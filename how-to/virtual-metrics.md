# Virtual Metrics (Custom Formulas) — своя колонка-формула в таблицах аналитики

**Virtual Metric — это собственная колонка-формула поверх уже существующих колонок таблицы отчёта: задаёшь формулу вроде `x / y` над двумя метриками таблицы, и в таблице появляется новая посчитанная колонка (например `EPC`).** Формула считается прямо в браузере поверх загруженных строк — на сервере такой метрики нет, серверную сущность `Metric` она не создаёт.

Инструмент `Custom formulas` — в верхней панели таблицы: в `Roll Up report` это кнопка-иконка калькулятора (тултип `Custom formulas`), в остальных таблицах — пункт `Custom formulas` в меню `Table tools`. Формулы привязаны к конкретной таблице, к конкретному пользователю и к тенанту.

## Что такое Virtual Metric и чем отличается от серверной Metric

Virtual Metric и серверная сущность `Metric` — **разные вещи, их легко перепутать**:

- **`Metric`** (серверная) — настраиваемый числовой показатель-колонка, заведённый в `Settings → Metrics`, считается на сервере, адресуется по UUID, служит осью колонок во всех отчётах аналитики. Полностью — [models/metric.md](../models/metric.md).
- **Virtual Metric** (клиентская) — локальная колонка-формула поверх уже показанных в таблице метрик. Не заводится в `Settings → Metrics`, не имеет серверного UUID, не участвует в API. Существует только в браузере пользователя для этой одной таблицы.

Если колонку создали через `Custom formulas`, это Virtual Metric: её конфигурация хранится в браузере пользователя. Для серверной `Metric` видимость зависит от доступа к ней и к отчёту.

## Где кнопка Custom formulas

`Custom formulas` стоит в верхней панели таблицы рядом с раскраской строк (`Colorize rows`) и есть ровно в тех же таблицах, что и она: `Roll Up report` (в MTK — `Analytics → Pivot Reports`), Tracker-таблицы кампаний, источников, Destinations и data-секций (`Countries`, `Days`, `Other`…), таблицы разделов `Meta` / `Google` / `TikTok` / `Marketing`, `Content → Landings` и ещё ряд списков с аналитическими колонками. На `Tracker → Visits` и `Tracker → Conversions` её нет. В `Roll Up report` это отдельная кнопка-иконка калькулятора (тултип `Custom formulas`), в остальных таблицах — пункт `Custom formulas` в меню `Table tools` (подсказка `Add your own columns calculated from other metrics by a formula, e.g. x / y * 100`). Если формулы уже заведены, рядом показывается их количество.

## Как задать формулу: label, format, formula, mapping

Формула Virtual Metric состоит из четырёх частей, которые задаются в попапе `Custom formulas`:

- **`Name`** (`label`) — имя колонки, которое пользователь вводит сам (например `EPC`), до 40 символов. Оно же становится заголовком новой колонки в таблице.
- **`Format`** (`format`) — как форматировать значение в ячейке. Выбирается из перечня (см. раздел «Форматы»), по умолчанию `Number`.
- **`Formula`** (`formula`) — арифметическое выражение с **буквами-переменными** (`x / y * 100`). Переменные — только буквы из разрешённого набора.
- **`Variables`** (`mapping`) — какая исходная аналитическая колонка таблицы стоит за каждой буквой. Например `x → visits`, `y → clicks`. Другую Virtual Metric выбрать источником нельзя.

Порядок в попапе: вводишь `Name`, выбираешь `Format`, пишешь `Formula` буквами, затем в блоке `Variables` для каждой встреченной в формуле буквы выбираешь исходную колонку (`Select metric`). Кнопка `Add formula` добавляет колонку, `Update` сохраняет правку существующей формулы; клик по формуле в списке `Existing formulas` открывает её на правку.

### Разрешённые буквы-переменные

В формуле можно использовать только буквы из набора: `x`, `y`, `z`, `a`, `b`, `c`, `d`, `e`, `f`, `g`, `h`, `i`, `k`. Другие буквенные токены переменными не считаются и в маппинг не попадают.

Каждая буква, встреченная в формуле, требует выбора исходной колонки в `Variables` — пока у какой-то буквы источник не выбран, кнопка `Add formula` / `Update` неактивна.

### Форматы значения (format)

Поле `Format` предлагает следующие значения (ключ конфигурации указан в скобках):

- **`Number`** (`number`) — число с двумя знаками после запятой.
- **`Number (profit)`** (`number-profit`) — то же число, с зелёной подсветкой положительных значений.
- **`Integer`** (`integer`) — целое число (без знаков после запятой).
- **`Money ($)`** (`money`) — денежный формат с двумя знаками.
- **`Money (profit)`** (`money-profit`) — денежный формат с зелёной подсветкой положительных значений.
- **`Percent (%)`** (`percent`) — процент с двумя знаками; дробь `0.25` показывается как `25.00%`.

Форматы с суффиксом `-profit` (`number-profit`, `money-profit`) подсвечивают положительные значения зелёным — удобно для колонок вроде профита или ROI.

### Пример: EPC как процент от визитов к кликам

Чтобы получить колонку `EPC` = визиты, делённые на клики, в процентах:

1. `label` — `EPC`.
2. `format` — `Percent (%)` (`percent`).
3. `formula` — `x / y`: процентный формат сам умножает дробь на 100 при отображении.
4. `mapping` — `x` → колонка визитов, `y` → колонка кликов.

После `Add formula` в таблице появляется колонка `EPC` со значением по каждой строке. Итог по таблице (footer) считается той же формулой по итоговым значениям исходных колонок — `сумма(визиты) / сумма(клики)`, показанная в процентах, а не сумма построчных `EPC`.

## Ограничения — что важно понимать заранее

Virtual Metrics — клиентская надстройка, и из этого следует несколько ограничений, которые надо держать в голове.

### Считается в браузере при загрузке данных

Значения Virtual Metric считаются **на стороне клиента** после того, как строки таблицы пришли с сервера. Формула применяется к уже загруженным строкам в браузере — сервер про эту колонку ничего не знает.

Следствие: колонка считается только по тем строкам, что реально загружены в таблицу. Доступна лишь базовая арифметика: `+`, `-`, `*`, `/`, скобки, степень `^` и функции `sqrt`, `sin`, `cos`, `tan` (угол — в градусах). Сложную логику формула не поддерживает; деление на ноль или ошибка в выражении дают в ячейке `N/A`.

### Хранится локально в браузере (per-table, per-user)

Формулы хранятся **локально в браузере** пользователя (`localStorage`) — по каждой таблице, пользователю и тенанту отдельно. На сервер они не уходят.

Практические следствия:

- Формула видна **только тому**, кто её завёл. Другой пользователь того же тенанта её не увидит.
- Формула привязана к **устройству и браузеру**. На другом компьютере или в другом браузере тех же формул не будет — они не синхронизируются между устройствами.
- Очистка данных браузера / другой профиль → формулы пропадут.

Если нужна формула, которая хранится и считается на сервере, заведите `Metric` типа `Computable metric` (формула из других метрик по UUID) и настройте доступ к ней. Разница — [models/metric.md](../models/metric.md).

### Не участвует в серверной сортировке и пагинации

Virtual Metric не уходит на сервер, поэтому она **не участвует в серверной сортировке и пагинации**. Сервер сортирует и разбивает страницы по своим колонкам; посчитанная в браузере колонка в этой сортировке не учитывается.

Практический вывод: сортировка у колонки Virtual Metric выключена — клик по её заголовку порядок строк не меняет, отсортировать таблицу по формуле нельзя.

## Типичные вопросы

- **«Завёл формулу, коллега её не видит»** — это ожидаемо: Virtual Metric локальна (per-user, per-table, в браузере). Нужна общая колонка → заводить серверную `Metric` ([models/metric.md](../models/metric.md)).
- **«Формула пропала после смены компьютера»** — тоже ожидаемо: хранится в браузере, между устройствами не синхронизируется.
- **«Колонка не показывает значение»** — проверь маппинг: каждая буква формулы должна быть сопоставлена с аналитической колонкой таблицы. Если источник отсутствует в наборе колонок этого отчёта, Virtual Metric не добавится в таблицу. Исходную метрику можно скрыть: видимая Virtual Metric продолжает запрашивать её данные для расчёта.
