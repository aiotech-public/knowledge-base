# Virtual Metrics (Custom Formulas) — своя колонка-формула в таблицах аналитики

**Virtual Metric — это собственная колонка-формула поверх уже существующих колонок таблицы отчёта: задаёшь формулу вроде `x / y` над двумя метриками таблицы, и в таблице появляется новая посчитанная колонка (например `EPC`).** Формула считается прямо в браузере поверх загруженных строк — на сервере такой метрики нет, серверную сущность `Metric` она не создаёт.

Кнопка — в топбаре таблицы отчёта (иконка калькулятора, подпись `Custom formulas`). Формулы привязаны к конкретной таблице и к конкретному пользователю.

## Что такое Virtual Metric и чем отличается от серверной Metric

Virtual Metric и серверная сущность `Metric` — **разные вещи, их легко перепутать**:

- **`Metric`** (серверная) — настраиваемый числовой показатель-колонка, заведённый в `Settings → Metrics`, считается на сервере, адресуется по UUID, служит осью колонок во всех отчётах аналитики. Полностью — [models/metric.md](../models/metric.md).
- **Virtual Metric** (клиентская) — локальная колонка-формула поверх уже показанных в таблице метрик. Не заводится в `Settings → Metrics`, не имеет серверного UUID, не участвует в API. Существует только в браузере пользователя для этой одной таблицы.

Практический вывод: «я добавил метрику, а её никто больше не видит» — это Virtual Metric (локальная формула), а не серверная `Metric`. Серверную метрику видят все пользователи тенанта, Virtual Metric — только тот, кто её завёл, и только на своём устройстве.

## Где кнопка Custom formulas

Кнопка `Custom formulas` живёт в топбаре таблицы отчёта — там же, где кнопка раскраски строк (`Colorize`). Иконка — калькулятор; если формулы уже заведены, на кнопке показывается их количество.

Кнопка доступна в drill-down таблицах аналитики (отчёты). Тех же таблицах, где работают `Colorize` и групперы.

## Как задать формулу: label, format, formula, mapping

Формула Virtual Metric состоит из четырёх частей, которые задаются в попапе кнопки `Custom formulas`:

- **`label`** — имя колонки, которое пользователь вводит сам (например `EPC`). Оно же становится заголовком новой колонки в таблице.
- **`format`** — как форматировать значение в ячейке. Выбирается из перечня (см. раздел «Форматы»).
- **`formula`** — арифметическое выражение с **буквами-переменными** (`x / y * 100`). Переменные — только буквы из разрешённого набора.
- **`mapping`** — какая колонка таблицы стоит за каждой буквой. Например `x → visits`, `y → clicks`.

Порядок в попапе: вводишь `label`, выбираешь `format`, пишешь `formula` буквами, затем для каждой встреченной в формуле буквы выбираешь исходную колонку. После `Save` колонка появляется в таблице.

### Разрешённые буквы-переменные

В формуле можно использовать только буквы из набора: `x`, `y`, `z`, `a`, `b`, `c`, `d`, `e`, `f`, `g`, `h`, `i`, `k`. Другие буквенные токены переменными не считаются и в маппинг не попадают.

Каждая буква, встреченная в формуле, требует выбора исходной колонки в маппинге — пока источник не выбран, формула не даст значения.

### Форматы значения (format)

Поле `format` берётся из фиксированного перечня — дословные значения:

- **`number`** — число с двумя знаками после запятой.
- **`number-profit`** — то же число, с зелёной подсветкой положительных значений.
- **`integer`** — целое число (без знаков после запятой).
- **`money`** — денежный формат с двумя знаками.
- **`money-profit`** — денежный формат с зелёной подсветкой положительных значений.
- **`percent`** — процент с двумя знаками.

Форматы с суффиксом `-profit` (`number-profit`, `money-profit`) подсвечивают положительные значения зелёным — удобно для колонок вроде профита или ROI.

### Пример: EPC как процент от визитов к кликам

Чтобы получить колонку `EPC` = визиты, делённые на клики, в процентах:

1. `label` — `EPC`.
2. `format` — `percent`.
3. `formula` — `x / y * 100`.
4. `mapping` — `x` → колонка визитов, `y` → колонка кликов.

После `Save` в таблице появляется колонка `EPC` со значением по каждой строке. Итог по таблице (footer) считается той же формулой, но по итоговым значениям исходных колонок — то есть `сумма(визиты) / сумма(клики) * 100`, а не сумма построчных `EPC`.

## Ограничения — что важно понимать заранее

Virtual Metrics — клиентская надстройка, и из этого следует несколько ограничений, которые надо держать в голове.

### Считается в браузере при загрузке данных

Значения Virtual Metric считаются **на стороне клиента** после того, как строки таблицы пришли с сервера. Формула применяется к уже загруженным строкам в браузере — сервер про эту колонку ничего не знает.

Следствие: колонка считается только по тем строкам, что реально загружены в таблицу. Доступна лишь базовая арифметика (`+`, `-`, `*`, `/`, степень, и функции вроде `sqrt`, `sin`, `cos`, `tan`) — сложную логику формула не поддерживает.

### Хранится локально в браузере (per-table, per-user)

Формулы хранятся **локально в браузере** пользователя (`localStorage`) — по каждой таблице и по каждому пользователю отдельно. На сервер они не уходят.

Практические следствия:

- Формула видна **только тому**, кто её завёл. Другой пользователь того же тенанта её не увидит.
- Формула привязана к **устройству и браузеру**. На другом компьютере или в другом браузере тех же формул не будет — они не синхронизируются между устройствами.
- Очистка данных браузера / другой профиль → формулы пропадут.

Если нужна колонка-показатель, которую видят все и которая живёт на сервере — это уже серверная `Metric` типа `Computable` (формула из других метрик по UUID), а не Virtual Metric. Разница — [models/metric.md](../models/metric.md).

### Не участвует в серверной сортировке и пагинации

Virtual Metric не уходит на сервер, поэтому она **не участвует в серверной сортировке и пагинации**. Сервер сортирует и разбивает страницы по своим колонкам; посчитанная в браузере колонка в этой сортировке не учитывается.

Практический вывод: нельзя «отсортировать всю таблицу по Virtual Metric» так, как по обычной колонке отчёта — серверный порядок строк формула не меняет.

## Типичные вопросы

- **«Завёл формулу, коллега её не видит»** — это ожидаемо: Virtual Metric локальна (per-user, per-table, в браузере). Нужна общая колонка → заводить серверную `Metric` ([models/metric.md](../models/metric.md)).
- **«Формула пропала после смены компьютера»** — тоже ожидаемо: хранится в браузере, между устройствами не синхронизируется.
- **«Колонка не показывает значение»** — проверь маппинг: каждая буква формулы должна быть сопоставлена с колонкой таблицы; если исходной колонки в текущей таблице нет (например сменили набор колонок или отчёт), формула не отрисуется.
