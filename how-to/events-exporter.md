# Events Exporter — выгрузка больших таблиц событий (Visits / Trash Visits / Conversions) в файл

`Events Exporter` выгружает события за выбранный период — до сотен миллионов строк — в скачиваемые файлы. Набор колонок задан для каждого датасета; строки ограничиваются тенантом и доступом пользователя к кампаниям и источникам. Три датасета: `Visits`, `Trash Visits`, `Conversions`. Процесс асинхронный: запускаешь выгрузку, а о готовности файлов приходит уведомление.

Как это называют / частые формулировки: «скачать сырые события», «экспорт визитов/конверсий в CSV», «выгрузка конверсий за период», «выгрузить визиты/конверсии в файл за диапазон дат».

Это не то же самое, что `External Report → CSV` (`Visits CSV` / `Google Conversions CSV`) в [how-to/api.md](api.md) — там другой механизм и другая задача (см. ниже «Events Exporter ≠ External Report CSV»).

---

## Зачем нужен Events Exporter — когда обычная выгрузка не тянет

`Events Exporter` рассчитан на выгрузку **сотен миллионов строк** сырых событий за раз. CSV-экспорт таблицы из интерфейса тоже работает в фоне, но выгружает строки настроенной таблицы и имеет собственный предел. Events Exporter создаёт отдельные суточные файлы выбранного датасета.

`Events Exporter` вместо этого ставит задачу в очередь и отдаёт данные файлами по дням: диапазон дат режется на суточные части, каждая часть пишется в отдельный файл. Поэтому подходит для выгрузки доступных событий за месяц отдельными файлами, а не агрегированной сводкой.

## Какие датасеты можно выгрузить — Visits, Trash Visits, Conversions

`Events Exporter` выгружает один из трёх датасетов на запуск:

- **Visits** (`visits`) — визиты с колонками атрибуции и состоянием визита. Выгружаются доступные пользователю строки за выбранный период.
- **Trash Visits** (`trash_visits`) — визиты, отсеянные фильтром/антифродом (боты, `blacklists`, junk-трафик — отсеяно правилами трафика). Это отдельная таблица от `Visits`, с урезанным набором полей ([reference/glossary.md](../reference/glossary.md) → `Trash / Trash Visits`).
- **Conversions** (`conversions`) — конверсии (события у рекламодателя, привязанные к визитам).

Датасет выбирается карточкой в диалоге запуска; в API — полем `dataset` со значениями `visits` / `trash_visits` / `conversions`. Любое другое значение отклоняется с ошибкой `Unknown dataset "<значение>"` (`422`) — допустимы только эти три (в UI это подписи `Visits` / `Trash Visits` / `Conversions`).

## В каком формате приходит файл — CSV (gzip) по умолчанию

В диалоге по умолчанию выбран **CSV**, сжатый gzip (`format: csv`) — файлы приходят с расширением `.csv.gz`. В диалоге запуска можно переключить формат на **Parquet** (`format: parquet`) — колоночный формат для аналитических инструментов, расширение `.parquet` (сжатие внутри самого формата). Других форматов нет: HTTP-запрос с `format`, отличным от `csv` / `parquet`, отклоняется при валидации.

Диапазон дат режется по дням: каждый день диапазона — отдельный файл (`part-<YYYYMMDD>.csv.gz` / `.parquet`). Пустые дни пропускаются, лишних файлов не создаётся. На выходе — набор файлов по дням плюс манифест (`manifest.json`), из которого их скачивать.

## Как запустить выгрузку через UI — Analytics → Events Exporter

Путь в интерфейсе: `Analytics → Events Exporter` — открывается диалог запуска выгрузки. Пункт доступен при праве `analytics.data-exporter`.

В диалоге:

1. Выбери датасет карточкой — `Visits` / `Trash Visits` / `Conversions`.
2. Задай диапазон дат `From` / `To` (включительно с обоих концов).
3. Выбери формат — `CSV` (по умолчанию) или `Parquet`.
4. Нажми запуск. Диалог закрывается, выгрузка уходит в фон.

Диапазон валидируется прямо в диалоге: если `To` раньше `From` или диапазон больше лимита в днях — кнопка запуска заблокирована с подсказкой (см. «Лимит диапазона дат»).

## Как запустить выгрузку через API — POST /api/v1/events-exporter/export

Endpoint: `POST /api/v1/events-exporter/export`. Тело запроса:

```jsonc
{
  "dataset":   "visits",          // visits | trash_visits | conversions
  "date_from": "2026-01-01",      // Y-m-d, включительно
  "date_to":   "2026-01-31",      // Y-m-d, включительно
  "format":    "csv"              // опц.: csv | parquet; без format — настройка платформы, её дефолт csv
}
```

Ответ `200` — выгрузка поставлена в очередь, файлов ещё нет:

```jsonc
{ "data": { "export_uuid": "…", "status": "pending" } }
```

`export_uuid` — идентификатор запущенной выгрузки. По нему приходит уведомление о готовности.

Ошибки `422` (невалидный запрос) приходят с дословным текстом причины:

- `Date range too large: <N> days (max <M>). Narrow the range.` — диапазон больше лимита (см. «Лимит диапазона дат»).
- `Unknown dataset "<значение>"` — недопустимое значение `dataset` (допустимы только `visits` / `trash_visits` / `conversions`).
- `date_from must be <= date_to` — конечная дата раньше начальной.

Формат и формат дат проверяются раньше — на входной валидации запроса, ещё до этих сообщений. Поэтому кривой `format` (не `csv` / `parquet`) или дата не в виде `Y-m-d` возвращают `422` со стандартным Laravel-сообщением валидации (типа «The selected format is invalid.» / «The date_from does not match the format Y-m-d.»), а не с текстом из списка выше. Тенант через API не передаётся в теле — он берётся из текущего пользователя, — так что ошибки «не передан тенант» на HTTP-пути нет.

При превышении лимита одновременных выгрузок приходит `429` с текстом `Too many concurrent exports for this tenant (<N> running/queued, limit <M>). Try again later.` (см. «Ошибка 429»).

## Как узнать, что файлы готовы — уведомление о готовности

Выгрузка асинхронная: сразу файлов нет, о готовности приходит **уведомление**. Одно уведомление живёт весь цикл выгрузки и обновляется по ходу — старт, прогресс (сколько частей из скольких уже готово), финал.

Заголовок уведомления меняется по фазам: `Export running` (идёт) → `Export ready` (готово, файлы можно скачивать) либо `Export failed` (сорвалось). Внутри `Export running` идёт прогресс-текст: `Export starting…` → `Counting rows…` → `Exported <n>/<N> days (<дата>)…` → на финализации сборка манифеста. Если выгрузка упала, в уведомлении абстрактный текст `Something went wrong during export` — реальная причина в него не кладётся, она уходит в лог. Если ошибка повторяется, напишите в поддержку.

### Куда приходит уведомление Events Exporter — интерфейс, Telegram, Slack

Уведомление о выгрузке приходит внутри интерфейса. Дополнительно оно может дублироваться в **Telegram** или **Slack** — если у пользователя настроена доставка этого типа уведомлений в нужный канал. Без такой настройки уведомление приходит только внутри интерфейса. Прогресс по ходу выгрузки виден только внутри интерфейса; в Telegram / Slack уходит только финальное (готово / ошибка).

### Что в готовом уведомлении и сколько живут ссылки на файлы

В готовом уведомлении Events Exporter — сводка (сколько строк, в скольких файлах, за какой диапазон) и ссылка на скачивание. Ссылки на файлы временные: срок задаётся настройкой платформы, по умолчанию **7 дней**. Каждая ссылка отсчитывает срок с момента её выпуска; ссылки на части создаются по ходу выгрузки, ссылка на манифест — при финализации. Срок указан в уведомлении и манифесте; сводка сроков и лимитов — [reference/limits.md](../reference/limits.md). Если ссылки истекли — запусти выгрузку тем же диапазоном заново.

Ссылка ведёт на домен AIO, а не в файловое хранилище, и открывается без входа в аккаунт — в том числе прямо из Telegram, куда уведомление могло продублироваться. Общие правила ссылок из уведомлений — [mechanics/notification-center.md](../mechanics/notification-center.md).

### Выгрузка не дала ни одного файла — `No rows found`

Если за выбранный датасет, диапазон дат и доступный тебе scope в базе нет ни одной строки, выгрузка не создаёт файлов, а в статусе выгрузки (поле `error`) стоит `No rows found for the given dataset / tenant / date range / scope`. Задание получает статус `failed`: за этот период нет данных под твоим доступом. Проверь датасет, даты и что у тебя есть доступ к нужным кампаниям/источникам, и запусти заново с корректным диапазоном.

## Как скачать готовые файлы — окно `Export manifest`

Из готового уведомления открывается окно `Export manifest` — список частей выгрузки, по строке на день. Сверху сводка: `Dataset`, `Range`, `Rows`, `Parts`, `Format` (у CSV дописано `· gzip (.csv.gz)`) и `Link TTL, days` — сколько дней живут ссылки.

В каждой строке — дата части и число строк в ней, справа кнопка `Download` и иконка `Copy link` (скопировать прямую ссылку на файл). В шапке списка — `Download all`, в футере — `Download manifest` (сам `manifest.json` со всеми ссылками) и `Close`.

### Скачивание одной части — процент, мегабайты и кнопка `Cancel`

При известном размере часть качается диапазонами силами интерфейса. Если размер определить не удалось, интерфейс скачивает её одним запросом. Пока идёт загрузка, вместо кнопок в строке части показывается прогресс, рядом — `Cancel`.

Прогресс — процент; если размер файла заранее неизвестен, вместо процента идут скачанные мегабайты (`12.3 MB`). Если доступен выбор файла через File System Access API и файл удалось открыть для записи, браузер спрашивает место сохранения и пишет части прямо в него. Иначе файл собирается в памяти и передаётся обычной загрузке браузера.

Успешное сохранение подтверждается тостом `<имя файла> saved`, неудача — `Download failed`. Причина кусков: одна часть бывает в сотни мегабайт, и одним запросом на медленном канале она не доезжает — оборвавшийся кусок докачивается сам, а не начинается весь файл заново.

### `Download all` — скачать все части разом

`Download all` в шапке списка тянет все части подряд, а как именно — зависит от браузера. Подсказка на кнопке говорит заранее, что будет: `Pick a folder once — files will be saved into it without prompts.` или `Browser will ask once to allow multiple downloads.`

При доступном выборе папки через File System Access API папка выбирается один раз, дальше части пишутся в неё по очереди без вопросов. Вместо кнопки идёт `Downloaded {done} of {total}…` и `Cancel`, уже сохранённые части подписаны `Saved`, ожидающие своей очереди — `Queued`. В конце — тост `Saved {n} files to the picked folder.`, при срыве — `Bulk download failed — links may have expired.`

Без выбора папки через File System Access API интерфейс запускает загрузки через скрытые iframe; браузер может попросить разрешить несколько загрузок, и появляется тост `Triggered {n} downloads — allow the prompt if your browser asks.` Прогресса по частям и подписей `Queued` / `Saved` в этом режиме нет.

### Большой файл можно дотянуть менеджером загрузок — сервер отдаёт диапазоны

Файлы выгрузки отдаются с поддержкой докачки на уровне протокола: в ответе стоит `Accept-Ranges: bytes`, `HEAD` отдаёт размер файла, запрос диапазона возвращает `206 Partial Content`. Поэтому ссылку из окна манифеста (`Copy link`) можно скормить стороннему менеджеру загрузок или `curl -C -` и дотянуть прерванный файл, не начиная заново.

Два ограничения. Составные диапазоны — несколько кусков в одном запросе — не поддерживаются: на такой запрос приходит `416`. Протухшая подпись ссылки даёт `403`, и повторять запрос бесполезно — нужно перезапустить выгрузку.

К ссылке нельзя дописывать свои параметры: подпись покрывает путь и весь query, и любой лишний параметр делает ссылку недействительной.

### Файлы не скачиваются, «links may have expired» — проверить срок ссылки

Симптом: окно `Export manifest` не открывается или скачивание падает — «ссылки протухли», download failed, expired.

Дословные сообщения: `Could not load manifest — links may have expired or CORS is blocking the request.` (не открылся сам манифест), `Bulk download failed — links may have expired.` (сорвалось скачивание всех частей), `Download failed` (сорвалась одна часть). Первое, что проверять по всем трём: истёк ли срок ссылки. По умолчанию он составляет 7 дней с её выпуска; срок также указан в уведомлении и манифесте. Эти сообщения сами по себе не доказывают истечение: они появляются и при других ошибках запроса.

Лечится перезапуском выгрузки тем же диапазоном — придёт новое уведомление со свежими ссылками. Повторные нажатия на старую ссылку не помогают: протухшая подпись отвечает `403` на каждую попытку.

## Лимит диапазона дат — до 31 дня за раз

В UI максимальный диапазон одной выгрузки — **31 день** включительно: для большего диапазона кнопка запуска заблокирована с подсказкой. Для API предел задаётся настройкой платформы, по умолчанию тоже 31 день (сводка лимитов — [reference/limits.md](../reference/limits.md)). Превышение действующего API-предела возвращает `422` с текстом `Date range too large: <N> days (max <M>). Narrow the range.`. Лимит защищает от случайного запроса на гигантский период.

Если нужно больше 31 дня — запусти несколько выгрузок подряд по 31-дневным окнам.

## Ошибка 429 — слишком много одновременных выгрузок

`429` с текстом `Too many concurrent exports for this tenant (<N> running/queued, limit <M>). Try again later.` означает срабатывание лимита запусков для этого тенанта (по умолчанию **2** — см. [reference/limits.md](../reference/limits.md)). При проверке учитываются задания, ожидающие запуска, и активный этап записи выгружаемых данных. Это не полный счётчик всех заданий со статусом `running`; повторный запуск может упереться в лимит. Один код `429` без указанного текста не подтверждает эту причину.

Дождись завершения текущих выгрузок — успешного или с ошибкой — и запусти снова.

## Events Exporter ≠ External Report CSV — не путать

`Events Exporter` и `External Report → CSV` (из [how-to/api.md](api.md)) — **разные механизмы под разные задачи**, несмотря на то что оба отдают CSV:

- **`Events Exporter`** — выгрузка **событий выбранного датасета в пределах доступа пользователя** (`Visits` / `Trash Visits` / `Conversions`), сотни млн строк, асинхронно, файлами по дням, готовность приходит уведомлением. Это раздел `Analytics → Events Exporter`.
- **`External Report → CSV`** (`Visits CSV` / `Google Conversions CSV`) — настраиваемый отчёт: `Visits CSV` скачивается синхронно по ссылке `external-reports/data`, а `Google Conversions CSV` — специально под загрузку офлайн-конверсий в Google Ads (Google сам ходит по ссылке и тащит CSV). Если запрос звучит как «выгрузить конверсии для Google Ads» — это про `Google Conversions CSV`, а не про `Events Exporter`. Настройка и полный разбор — [how-to/api.md](api.md) → «External Report → CSV-экспорт».

Коротко: `Events Exporter` — «выгрузить доступные события за период в файлы», `External Report CSV` — «настроенный отчёт по ссылке» (в частности, скармливаемый Google Ads).
