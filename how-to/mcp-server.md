# MCP-сервер AIO — подключить внешнего AI-агента

**У AIO есть свой MCP-сервер: внешний AI-агент — Claude Code, Claude Desktop, Perplexity, любой другой MCP-клиент — подключается к нему одной ссылкой и дальше сам ходит за данными трекера: трафик, метрики, прогнозы, логи кампаний, справка по продукту.** Ссылку с готовой командой и конфигом собирает диалог `MCP Server` в окне `AIO Chat`. Доступ — только на чтение и только под правами того юзера, чей API-токен вставлен в ссылку.

---

## Что такое MCP-сервер AIO и зачем он нужен

`MCP Server` — эндпоинт `POST https://app.aio.tech/api/v1/mcp`, который отдаёт внешнему AI-агенту инструменты AIO. Агент сам решает, какой из них вызвать под ваш вопрос: спрашиваете «покажи трафик за сегодня по странам» — он берёт данные из AIO и отвечает.

Смысл в том, что агент живёт вне AIO — в терминале, в десктопном приложении, в чужом чате — и всё равно видит ваши цифры. Своего кода под это писать не нужно: ни разбора запросов через F12, ни обвязки поверх API.

Чем это отличается от встроенного ассистента `AIO Chat` ([how-to/ai-chat.md](ai-chat.md)): чат работает в интерфейсе и рисует ответ таблицами и графиками, а MCP отдаёт данные вашему агенту — как их показать и что с ними делать дальше, решает он.

## Как подключить агента: кнопка `MCP` в окне `AIO Chat`

Ссылка на сервер собирается в диалоге `MCP Server`. Открыть его можно двумя путями: кнопкой **`MCP`** в тулбаре окна `AIO Chat` (тултип «Подключить внешнего агента к MCP-серверу AIO») или карточкой «Подключите Claude Code, Cursor или другого агента» на стартовом экране пустого чата → `Настроить`. Нет ни кнопки, ни карточки — значит тенанту не подключён сам `AIO Chat`: диалог живёт в его окне и пропадает вместе с ним (разбор — [how-to/ai-chat.md](ai-chat.md)).

Дальше в диалоге четыре поля:

1. **`API-токен`** — вставьте свой токен. Поле всегда пустое: токен нигде не сохраняется, каждый раз вводится руками. Где взять токен — [how-to/api.md](api.md).

2. **`Тенант`** — подставляется текущий из свитчера, менять в диалоге нечего. Нужна ссылка на другой тенант — переключите тенант и откройте диалог заново.

3. **`URL сервера`** — готовая ссылка вида `https://app.aio.tech/api/v1/mcp?token=<токен>&tenant=<uuid тенанта>`.

4. **`Агент`** — выберите своего: `Claude Code`, `Claude Desktop`, `Perplexity`, `OpenClaw`, `NemoClaw`, `Hermes`. Под выбранного подставляются три шага инструкции, готовая `Команда` или `Конфиг` и текст-промпт («Или просто вставьте это агенту в чат») — агент по нему настроит себя сам.

### `Claude Code` — одна команда в терминале

Диалог отдаёт готовую строку: `claude mcp add --transport http aio "<ссылка из диалога>"`. Выполнить её можно в любой папке — Claude Code сохранит сервер в своём конфиге; проверить, что он там, командой `claude mcp list`.

Дальше запускаете `claude` и спрашиваете словами: «Покажи трафик за сегодня по странам» — инструменты AIO агент вызовет сам.

### `Claude Desktop`, `Perplexity` и остальные — JSON-конфиг `mcpServers`

MCP-клиентам без своего CLI диалог отдаёт готовый конфиг:

```json
{"mcpServers": {"aio": {"type": "http", "url": "<ссылка из диалога>"}}}
```

- **`Claude Desktop`** — `Settings → Connectors → Add custom connector` и вставить `URL сервера`; либо `Settings → Developer → Edit Config` с конфигом выше и перезапуск приложения.
- **`Perplexity`** — `Settings → Connectors → Add connector → MCP`, вставить `URL сервера` (или тот же конфиг).
- **`OpenClaw`, `NemoClaw`, `Hermes`** — добавить сервер в конфиг агента (секция `mcpServers`, HTTP-транспорт) и перезапустить его.

Проверка подключения у всех одна: попросить агента перечислить инструменты `aio`. Список виден — связь есть.

### Ссылка содержит ваш токен — не делитесь ей и не коммитьте

Токен зашит прямо в `URL сервера`, поэтому ссылка на MCP-сервер — это пароль от API: она уезжает в конфиг агента, историю терминала и репозиторий. В диалоге про это сказано отдельной строкой: «Токен в ссылке — это полный доступ к API от вашего имени. Не делитесь ей и не коммитьте». Что делать с утёкшей ссылкой и почему перевыпустить токен самостоятельно нельзя — [how-to/api.md](api.md).

Права у подключённого агента ровно те же, что у юзера, чей токен вставлен: чужих кампаний и чужих настроек он не увидит. Отозвать доступ у уже настроенного агента можно двумя путями. Деактивация юзера в тенанте (`Manage Tenant → юзер → Deactivate`, разбор — [how-to/permissions.md](permissions.md)) сразу закрывает агенту **этот тенант**: на ссылку с `?tenant=` приходит `403` `Tenant is not available`. Но сам токен при этом жив и продолжает работать в остальных тенантах юзера — агента достаточно перенастроить на другой `?tenant=`. Отрезает полностью только снятие юзеру API-доступа или смена токена, и то и другое делает команда AIO ([how-to/api.md](api.md)).

## Что нужно, чтобы ссылка заработала

### Агент получает `401` — проверьте, включён ли API-доступ

`401` `Auth Middleware: Unauthorized` на любой запрос к MCP-серверу чаще всего означает, что не подошёл токен. Три причины: токен неверный, юзер деактивирован или **у юзера выключен API-доступ** (колонка `API` в `Settings → Users`). Четвёртый источник того же `401` — чужой тенант в заголовке `x-tenant-id` (разбор — «Тенант в MCP обязателен — без него `400`» ниже).

API-доступ включает команда AIO по запросу — в самом диалоге на это указывает строка «Нет API-токена или API-доступ выключен? — Запросите его у поддержки». Полный разбор причин отказа по токену — [how-to/api.md](api.md).

### Тенант в MCP обязателен — без него `400`

MCP-серверу тенант надо назвать явно: заголовком `x-tenant-id` или параметром `?tenant=<uuid>` в ссылке (диалог подставляет его сам). Тихого фоллбэка «возьмём тенант, выбранный у юзера», как в Data API ([how-to/api.md](api.md)), здесь нет — MCP-клиент обязан однозначно сказать, чей это тенант.

Что придёт в ответ, если с тенантом не так:

- `400` `Tenant is required: pass x-tenant-id header or ?tenant=<uuid>` — тенант не передан вовсе.
- `403` `Tenant is not available` — тенант в `?tenant=` не ваш либо юзер в нём неактивен.
- `401` `Auth Middleware: Unauthorized` — чужой тенант в заголовке `x-tenant-id`: такой запрос отбивается раньше, на авторизации.

## Какие инструменты AIO видит подключённый агент

Наружу отдаются **восемь читающих инструментов** — тот же набор, которым пользуется `AIO Chat` ([how-to/ai-chat.md](ai-chat.md)), минус презентационный: рисовать блоки интерфейса AIO вне интерфейса нечем.

Имена инструментов агент показывает дословно, по ним же его и просят («вызови `list_metrics`»). Описания инструментов и приветственная подсказка сервера — на русском. Данные каждого инструмента режутся правами юзера, чей токен в ссылке; отдельного права «на MCP» нет.

### Трафик, метрики и измерения — `traffic_analytics`, `list_metrics`, `list_dimensions`

- **`traffic_analytics`** — показатели трафика за период: `period.from` / `period.to` и `metrics[]` обязательны, дальше опционально `group_by` (разбивка по измерению), `filters`, `country_codes`, `compare_previous_period` (сравнить с прошлым периодом), `limit` — по умолчанию 50 строк, максимум 1000.

- **`list_metrics`** — каталог доступных метрик с описаниями: `search`, `limit` (по умолчанию 100, максимум 500). Отсюда берут точное имя метрики для `traffic_analytics`.

- **`list_dimensions`** — каталог измерений, то есть ключей для `group_by` и `filters`: `search`, `limit` (по умолчанию 50, максимум 200).

### Прогноз, история кампании и крео — `forecast`, `campaign_logs`, `get_ad_preview`

- **`forecast`** — прогноз метрики: `metric` обязателен, дальше `horizon` (шагов вперёд, по умолчанию 14, максимум 128), `granularity` (`hour` / `day` / `week` / `month`), опционально `period`, `filters`, `country_codes`. Возвращает историю и прогноз с коридором `p10–p90`.

- **`campaign_logs`** — история изменений кампании: `campaign` (UUID или human_id вида `007567`), `period` (опционально; без него берётся окно от 180 дней назад до текущего момента — в описании инструмента, которое читает агент, стоит «последние 14 дней», фактическое окно шире), `limit` (по умолчанию 200, максимум 500), `include_system` (по умолчанию видны только правки людей, системные записи скрыты).

- **`get_ad_preview`** — найти Facebook-объявление: `ad_id` — его facebook_id (значение из разбивки по измерению `Ads`) или uuid. Возвращает `ad_uuid`, `ad_id`, имя объявления и признак видео; саму карточку креатива с вариациями по языкам, таргетингом и бюджетом рисует интерфейс AIO — по MCP приходят только эти поля.

### Справка по продукту и свои алерты — `aio_knowledge_base`, `self_notify`

- **`aio_knowledge_base`** — ответ на вопрос про сам продукт AIO («как настроить домен», «что такое Distribution»); единственный параметр `question`. Если ответа нет, вернётся «В базе знаний нет ответа на этот вопрос».

- **`self_notify`** — ваши правила уведомлений ([mechanics/notification-center.md](../mechanics/notification-center.md)). Через MCP работает только `action: list` — посмотреть свои алерты и настройки каналов. Создать, изменить или удалить правило через MCP нельзя: эти действия отклоняются, их делают в окне `AIO Chat`.

## Через MCP можно только читать — изменения отклоняются

Любое действие, которое требует подтверждения человеком, MCP отклоняет **до** исполнения: агент получает ответ «Действие требует подтверждения человеком и через MCP недоступно — используйте AIO-чат». В диалоге это сказано прямо: «Доступны только читающие инструменты. Действия, требующие подтверждения, отклоняются — для них используйте AIO Chat».

Под этим гейтом три действия `self_notify` — `create`, `update`, `delete`. Посмотреть свои правила (`action: list`) агент может, а завести или поправить алерт — только в окне чата, где действие выносится карточкой `Разрешить` / `Отклонить` ([how-to/ai-chat.md](ai-chat.md)).

Так что через MCP не выйдет ни создать кампанию, ни поставить её на паузу, ни поменять ставку: инструментов на это нет в принципе. Но писать свой код ради типовой автоматизации над Meta не нужно — останавливать сущности и двигать бюджет по условиям умеет раздел `Automations` (только ERP, разбор — [how-to/auto-rules.md](auto-rules.md)). Своя обвязка на API ([how-to/api.md](api.md)) нужна там, где нужного действия нет ни в правилах, ни в чате.

## Чего ждать от агента: частые вопросы

### «Агент не знает такой метрики» — пусть сначала вызовет `list_metrics`

Описания инструментов ссылаются на каталоги «Доступные метрики» и «Измерения», которые подставляются в системный промпт `AIO Chat`; MCP-клиент этого промпта не получает. Поэтому точные имена метрик и ключи измерений агент должен забрать сам — вызвать `list_metrics` и `list_dimensions`, а уже оттуда подставить значения в `traffic_analytics`.

### «Агент ругается `Unknown tool: show_block`»

Ответ `-32602` `Unknown tool: show_block` — ожидаемый. `show_block` рисует блок в интерфейсе AIO и наружу не отдаётся, при этом описания `forecast` и `get_ad_preview` просят показать результат через него. Данные к этому моменту уже получены — агент просто покажет их своими средствами.

### «Ответ приходит текстом, а не таблицей»

MCP отдаёт результат текстом (JSON): готовых таблиц, графиков, воронок и KPI-карточек AIO через него не бывает — их рисует окно `AIO Chat` ([how-to/ai-chat.md](ai-chat.md)). Как показать данные, решает агент на своей стороне.

## Сколько запросов выдержит MCP — свой минутный лимит и общие с API потолки

У MCP-сервера **свой минутный счётчик**, отдельный от минутного лимита обычного API: серии `tools/call` от агента не съедают его и наоборот. По умолчанию это **600 запросов в минуту** на юзера. Симптом превышения — `429 Too Many Requests`. Как считается этот бюджет — [reference/limits.md](../reference/limits.md).

Два других потолка токена — бюджет тяжёлых запросов (Heavy query) и число одновременных запросов — у MCP **общие** со всем остальным API: они считаются на юзера целиком, без разделения по поверхностям. Поэтому серия тяжёлых `traffic_analytics` от агента тратит тот же бюджет, что и ваши обычные интеграции, и в `429` может уронить их тоже; сами числа и разбор — [how-to/api.md](api.md).

## Как устроен протокол — для ручного подключения

Сервер говорит по JSON-RPC 2.0 поверх Streamable HTTP и работает **stateless**: методы `initialize`, `tools/list`, `tools/call`, `ping`; `serverInfo` — имя `AIO ERP`, версия `1.0.0`. Поддерживаемые версии протокола — `2025-06-18` (по умолчанию), `2025-03-26`, `2024-11-05`.

Что учесть, если настраиваете MCP-клиент руками:

- SSE-стрима нет — ответ приходит одиночным JSON.
- `GET` на эндпоинт отвечает `405` с заголовком `Allow: POST`.
- Батч-запрос (массив сообщений) поддерживается; запрос из одних нотификаций возвращает `202` без тела.
- Незнакомое имя инструмента — ошибка `-32602` `Unknown tool: <имя>`.
