# Landing QA (AI-ревью кода лэнда)

**`Landing QA` — это AI-проверка HTML-кода лэнда прямо в редакторе: она находит проблемы и отдаёт рекомендации, часть которых можно применить кнопкой.** Это не рендер лэнда для просмотра (для этого есть `Full preview` и `Embed preview` — см. [how-to/landings.md](landings.md)), а ревью самого кода: разметка, недостающие/лишние макросы AIO, атрибуты. Запускается кнопкой `QA` в редакторе конкретного лэнда или Custom PWA, результат можно применить обратно в код одним кликом.

## Как открыть Landing QA

Кнопка `QA` живёт в шапке редактора лэнда, рядом с переключателем режимов `Code` / `Visual` / `Split` / `Full preview`.

1. Открой лэнд в редакторе: `Content → Landings` → правый клик по лэнду → `Manage landing`.
2. В шапке справа — кнопка `QA` (радужная, с иконкой-звёздочкой), тултип `Run AI quality check on this landing`.
3. Нажми `QA` — проверка стартует сразу, в компактном окне без заголовка; когда она закончится, окно раскроется на весь экран с шапкой `Landing QA` (секция «Что видно, пока идёт проверка, и можно ли её отменить»).

Кнопки `QA` нет в двух случаях: лэнд ещё не сохранён (у черновика нет UUID — сохрани лэнд) или для рабочего пространства не подключены AI-функции — их доступность регулирует команда AIO, и тогда в шапке нет и иконки `AI`, а в визуальном редакторе — кнопок `AI edit of the block` и `AI section` ([how-to/ai-chat.md](ai-chat.md), «Где доступен»; редактор — [how-to/landing-visual-editor.md](landing-visual-editor.md)). В этом случае — написать команде AIO.

Та же кнопка `QA` есть в шапке редактора страницы в `Manage Custom PWA` ([how-to/custom-pwa.md](custom-pwa.md)): у созданной PWA, чей ZIP уже разобран; у новой PWA до загрузки ZIP редактора нет. Режимов там три — `Code` / `Visual` / `Split`, без `Full preview`.

## Какую версию HTML проверяет Landing QA

**Landing QA читает сохранённый HTML основного лэнда; несохранённые правки редактора в проверку не входят.** Перед запуском сохрани изменения. В архиве с несколькими страницами QA проверяет основную страницу, даже если в редакторе открыта другая. У Custom PWA проверяется сохранённый HTML её страницы.

## Что видно, пока идёт проверка, и можно ли её отменить

**Отменить проверку нельзя: `Close`, `Esc` или клик мимо окна только закрывают окно, а прогон на сервере доходит до конца, и его результат в закрытое окно уже не придёт.** Нужен результат — нажми `QA` заново (это новый прогон).

Пока идёт проверка, окно компактное и без шапки. В нём логотип AI и фраза, которая раз в 4 секунды сменяется: `Reading the page…`, `Thinking it over…`, `Picking the right words…`, `Writing…`, `Matching the tone…`, `Checking the facts…`, `Polishing the text…`, `Almost there…` — они декоративные и ход проверки не отражают. Реальный этап — строка ниже, всегда на английском: `Loading landing…` → `Preparing skeleton…` → `AI is reviewing the landing…` (на большом лэнде `AI is reviewing the landing in N parts…`, затем `AI reviewed N/M parts…`) → `Finalizing report…`, под ней полоска с процентом. Если проверка упала (`Task failed`), окно остаётся компактным, а шапка возвращается.

## Что показывает результат

Диалог `Landing QA` подписан `AI-assisted review of this landing — recommendations only, no changes applied` — сам по себе он ничего в лэнде не меняет, пока ты не применишь фиксы. Результат делится на две части.

**Слева — просмотр лэнда** с переключателем `Preview` / `Code`: `Preview` рендерит сохранённый HTML, полученный для этого прогона, с применёнными в диалоге фиксами; `Code` показывает эту же копию. По ходу применения фиксов обе панели обновляются.

**Справа — метрики прогона и список рекомендаций.** Блок метрик:

- `Text blocks` — число фрагментов, вынесенных в карту при подготовке кода: текст, стили и адреса ресурсов, а не только текстовые блоки.
- `Chunks` — число частей, переданных на проверку: 1 при одном проходе, на большом лэнде — части HTML без служебной обёртки.
- `Auto-fixable` — число рекомендаций с авто-фиксом; применимость каждого фикса к текущей копии HTML проверяется отдельно.
- `LLM calls` — число учтённых вызовов модели за прогон.
- `Cost` — стоимость прогона в долларах.

## Рекомендации и авто-фиксы

Список `Recommendations` — это найденные проблемы, каждая с уровнем важности (critical / warning / info — видно по иконке). Над списком — фильтр по уровню (`All` / `Critical` / `Warn` / `Info`) со счётчиком в каждой кнопке. Когда в текущем фильтре нет рекомендаций, QA пишет `No issues — looks clean.`; проверь также `All`.

### Два способа применить фикс

Часть рекомендаций QA умеет применить автоматически — у такой строки есть кнопка `Apply`. Пути два:

- **`Apply` у отдельной рекомендации** — применяет только этот фикс. В режиме `All` после применения строка помечается `Applied`. Для отдельных фиксов оставь фильтр `All`.
- **`Apply all safe`** (кнопка у заголовка `Recommendations`, появляется когда `Auto-fixable` > 0) — прогоняет по порядку все авто-фиксы, которые применимы к текущему коду.

Пока ты не применил ни одного фикса, в футере только `Close`. Как только применён хотя бы один — футер меняется на `Discard changes` (откатить и закрыть без изменений) и `Apply to editor`.

### Какие авто-фиксы можно применить

Доступность `Apply` проверяется для каждого фикса. Для правки атрибута селектор должен попадать ровно в один элемент; если под селектор подходит несколько элементов или ни одного, кнопка `Apply` для этой рекомендации не показывается, а `Apply all safe` такой фикс пропускает. Типичные авто-фиксы — добавить недостающий макрос AIO в нужное место (`<head>` или перед `</body>`) или проставить атрибут элемента. Перед `Apply to editor` сверь изменения в `Code`.

## Как перенести фиксы в лэнд

`Apply` и `Apply all safe` меняют только временную копию внутри диалога — **сам лэнд ещё не тронут**. Чтобы правки попали в редактор:

1. Применённые фиксы должны быть видны (футер показывает `Apply to editor`).
2. Нажми `Apply to editor` — копия HTML из QA заменит HTML открытой страницы редактора (режим редактора — `Code` / `Visual` / `Split` — остаётся тот, что был открыт).
3. Дальше это обычная правка лэнда: её надо **сохранить** в редакторе, как любое ручное изменение (см. [how-to/landings.md](landings.md), раздел про Merged/Original-версии архива). В Custom PWA `Apply to editor` подставляет HTML в редактор PWA, а сохраняет правку кнопка `Save` диалога `Manage Custom PWA` — архив при этом не перезаливается ([how-to/custom-pwa.md](custom-pwa.md)).

Если передумал — `Discard changes` закрывает диалог, не трогая лэнд.

## Проверка упала: `Task failed` — что значит текст ошибки и что делать

Если AI-прогон не удался, диалог показывает карточку `Task failed` с причиной, в футере — `Retry` (запустить заново, новым прогоном) и `Cancel`. Те же диалог и общие тексты — у AI-правки блока, AI-вариантов, AI-секции ([how-to/landing-visual-editor.md](landing-visual-editor.md)), AI-описания и AI-отзывов PWA ([how-to/pwa-ai-texts.md](pwa-ai-texts.md)).

- `The AI service is temporarily overloaded — please try again in a minute` — AI-сервис перегружен или недоступен (обрыв, `429` / `5xx`); AIO уже сам повторил запрос несколько раз — подожди минуту и нажми `Retry`.
- `The AI request failed (HTTP <код>) — please try again` — AI-сервис отклонил запрос с другой HTTP-ошибкой; нажми `Retry` для нового прогона.
- `Anthropic output truncated (hit max_tokens=<N>). Reduce chunk size or input.` — ответ модели оборвался по лимиту длины; `Anthropic declined the request` — модель отказалась обрабатывать запрос; `Anthropic: no JSON result in response` — модель ответила не в формате результата.
- `Landing too large for QA: <N> bytes (limit <лимит>)` — превышен лимит размера ([reference/limits.md](../reference/limits.md)); `Landing has no HTML` — у лэнда нет сохранённого HTML.
- `Could not start the task. Please try again.` — задачу не удалось запустить; `The task failed unexpectedly.` — сбой без текста причины.

### Большой лэнд: `Could not review part N/M` в рекомендациях

Большой лэнд проверяется по частям, и сбой одной части прогон не роняет: прогон продолжается, а для непроверенной части в `Recommendations` появляется рекомендация уровня warning (считается в фильтре `Warn · N`) с текстом `Could not review part N/M: <причина>` — причина техническая (код HTTP с ответом AI-сервиса или один из текстов выше). `Retry` после завершённой проверки нет: чтобы перепроверить, закрой диалог и снова нажми `QA`.

## Билд-доступность

`Landing QA` доступна и в `ERP`, и в `MTK`: раздел лэндов и редактор `Manage landing` есть в обоих билдах, а кнопка `QA` показывается у сохранённого лэнда при подключённых для рабочего пространства AI-функциях (секция «Как открыть Landing QA») без отдельного ограничения по билду. Та же кнопка есть в редакторе Custom PWA; в MTK раздел `PWA + Push` появляется в меню при включённом модуле и доступных правах; доступ к странице PWA требует `content.landings.view.pwa` ([how-to/custom-pwa.md](custom-pwa.md)).

## Landing QA vs превью лэнда — не путать

- **`Landing QA`** — AI-ревью **кода** лэнда: находит проблемы разметки/макросов и предлагает авто-фиксы. Меняет код (после `Apply to editor` + сохранения).
- **`Full preview` / `Embed preview` / Quick Preview** — просто **рендер** лэнда для просмотра, без анализа кода и без правок. Статичное превью, плейсхолдеры визита не подставляются.
- **`Generate Visit by 1Step Preview Link`** — прогон лэнда глазами реального визита (с подстановкой плейсхолдеров), для отладки рантайма.

- **AI-правка блока** (`Edit with AI` в визуальном редакторе) — переписывает по просьбе один выделенный блок, а не проверяет весь лэнд — [how-to/landing-visual-editor.md](landing-visual-editor.md).

Все три превью-механизма описаны в [how-to/landings.md](landings.md).
