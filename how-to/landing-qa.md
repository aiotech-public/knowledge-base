# Landing QA (AI-ревью кода лэнда)

**`Landing QA` — это AI-проверка HTML-кода лэнда прямо в редакторе: она находит проблемы, отдаёт список рекомендаций и часть из них применяет автоматически.** Это не рендер лэнда для просмотра (для этого есть `Full Preview` и `Embed Preview` — см. [how-to/landings.md](landings.md)), а ревью самого кода: разметка, недостающие/лишние макросы AIO, атрибуты. Запускается кнопкой `QA` в редакторе конкретного лэнда, результат можно применить обратно в код одним кликом.

## Как открыть Landing QA

Кнопка `QA` живёт в шапке редактора лэнда, рядом с переключателем режимов `Code` / `Visual` / `Split` / `Full preview`.

1. Открой лэнд в редакторе: `Content → Landings` → правый клик по лэнду → `Manage landing`.
2. В шапке справа — кнопка `QA` (радужная, с иконкой-звёздочкой), тултип `Run AI quality check on this landing`.
3. Нажми `QA` — откроется диалог `Landing QA`, проверка стартует сразу.

Кнопка `QA` появляется **только у уже сохранённого лэнда** — у него есть UUID, который QA передаёт на проверку. Если лэнд ещё не сохранён (черновик без UUID), кнопки нет: сначала сохрани лэнд, потом запускай QA.

Пока идёт проверка, в диалоге видно статус (`Starting the task…` → прогресс с процентом). Проверка отменяема — закрой диалог кнопкой `Close`.

## Что показывает результат

Диалог `Landing QA` подписан `AI-assisted review of this landing — recommendations only, no changes applied` — сам по себе он ничего в лэнде не меняет, пока ты не применишь фиксы. Результат делится на две части.

**Слева — просмотр лэнда** с переключателем `Preview` / `Code`: `Preview` рендерит текущую версию лэнда (с уже применёнными фиксами, если ты их применил), `Code` показывает её HTML. По ходу применения фиксов обе панели обновляются.

**Справа — метрики прогона и список рекомендаций.** Блок метрик:

- `Text blocks` — сколько текстовых блоков лэнда разобрано.
- `Chunks` — на сколько кусков разбит код для проверки.
- `Auto-fixable` — сколько найденных проблем QA умеет починить автоматически.
- `Model` — какая AI-модель прогнала проверку.
- `LLM calls` — сколько запросов к модели ушло на этот прогон.
- `Cost` — стоимость прогона в долларах.

## Рекомендации и авто-фиксы

Список `Recommendations` — это найденные проблемы, каждая с уровнем важности: `Critical` / `Warning` / `Info`. Над списком — фильтр по уровню (`All` / `Critical` / `Warn` / `Info`) со счётчиком в каждой кнопке. Если проблем нет — QA пишет `No issues — looks clean.`

### Два способа применить фикс

Часть рекомендаций QA умеет применить автоматически — у такой строки есть кнопка `Apply`. Пути два:

- **`Apply` у отдельной рекомендации** — применяет только этот фикс. После применения строка помечается `Applied`.
- **`Apply all safe`** (кнопка у заголовка `Recommendations`, появляется когда `Auto-fixable` > 0) — прогоняет по порядку все безопасные фиксы, которые применимы к текущему коду.

Пока ты не применил ни одного фикса, в футере только `Close`. Как только применён хотя бы один — футер меняется на `Discard changes` (откатить и закрыть без изменений) и `Apply to editor`.

### Что считается безопасным фиксом

Фикс применяется, только если он однозначен. Например, правка атрибута применяется, когда её селектор попадает ровно в один элемент; если под селектор подходит несколько элементов или ни одного, кнопка `Apply` для этой рекомендации не показывается, а `Apply all safe` такой фикс пропускает. Типичные авто-фиксы — добавить недостающий макрос AIO в нужное место (`<head>` или перед `</body>`) или проставить атрибут элемента.

## Как перенести фиксы в лэнд

`Apply` и `Apply all safe` меняют только временную копию внутри диалога — **сам лэнд ещё не тронут**. Чтобы правки попали в редактор:

1. Применённые фиксы должны быть видны (футер показывает `Apply to editor`).
2. Нажми `Apply to editor` — исправленный HTML подставится в редактор лэнда (в HTML текущей страницы; режим редактора — `Code` / `Visual` / `Split` — остаётся тот, что был открыт).
3. Дальше это обычная правка лэнда: её надо **сохранить** в редакторе, как любое ручное изменение (см. [how-to/landings.md](landings.md), раздел про Merged/Original-версии архива).

Если передумал — `Discard changes` закрывает диалог, не трогая лэнд.

Если проверка упала (`Task failed`), в футере будет `Retry` (перезапустить прогон) и `Cancel`.

## Билд-доступность

`Landing QA` доступна и в `ERP`, и в `MTK`: раздел лэндов и редактор `Manage landing` есть в обоих билдах, а кнопка `QA` показывается по факту сохранённого лэнда без отдельного ограничения по билду.

## Landing QA vs превью лэнда — не путать

- **`Landing QA`** — AI-ревью **кода** лэнда: находит проблемы разметки/макросов и чинит безопасные из них. Меняет код (после `Apply to editor` + сохранения).
- **`Full Preview` / `Embed Preview` / Quick Preview** — просто **рендер** лэнда для просмотра, без анализа кода и без правок. Статичное превью, плейсхолдеры визита не подставляются.
- **`Visit by 1Step Preview Link`** — прогон лэнда глазами реального визита (с подстановкой плейсхолдеров), для отладки рантайма.

Все три превью-механизма описаны в [how-to/landings.md](landings.md).
