# User fields — поля визита прямо в карточках Source, Campaign, лендинга и Destination

Значение поля визита задаётся не только ссылкой и не только скриптом на лэнде — его можно вписать прямо в карточку настроечной сущности: `Source`, `Campaign`, лендинга, `Destination`, а также их «родителей» — `Flow`, `Lander Type`, `Advertiser`. За это отвечает секция `User fields` (`Пользовательские поля`) в форме.

Определение поля — имя, slug, `Type`, `Format`, `Available Values` — описано в [how-to/custom-fields.md](custom-fields.md).

В ERP само поле сначала заводится в `Settings → Fields`.

В MTK раздела `Fields` в Settings нет; создание нового поля — [how-to/custom-fields.md](custom-fields.md).

Базовый набор полей приходит с шаблоном тенанта при его создании ([context/architecture.md](../context/architecture.md)); ещё часть приезжает из шаблона источника: если в коде источника есть блок `fields`, недостающие поля AIO заводит при сохранении Source сам ([models/source.md](../models/source.md)). Концепт поля визита, кто в него пишет и в каком порядке значения перебивают друг друга — [models/visit-field.md](../models/visit-field.md).

## Что такое секция `User fields` в карточке сущности

`User fields` — блок в форме сущности со списком полей визита, значения которых задаются прямо в этой карточке. Одна строка блока = одно поле: слева инпут со значением, у собственной строки справа кнопка удаления; унаследованную строку удалить нельзя. Под списком доступна кнопка `Add field`, если ещё есть поля для добавления.

Набор полей формы и сами значения хранятся раздельно. Набор — это «какие поля вообще показывать в этой карточке», значения — что в них вписано. Порядок строк = порядок, в котором поля добавляли.

Если строк ещё нет, но есть доступные поля для добавления, секция показывает `No fields added yet` (`Поля ещё не добавлены`). Если нет ни строк, ни доступных полей, секция скрыта.

## В какой карточке какие поля доступны — пул задаётся `Type` поля

В форму попадают только поля с подходящим `Type`, у каждой карточки свой пул. Родительская сущность работает с пулом своего ребёнка: у `Flow` это поля `Campaign`, у `Lander Type` — `Landing`, у `Advertiser` — `Destination`.

| Карточка | Пул полей (`Type`) |
|---|---|
| `Source` | `Source` |
| трафиковая `Campaign` | `Campaign` |
| лендинг | `Landing` |
| `Destination` | `Destination` |
| `Advertiser` | `Destination` |

У лендинга секция есть в редакторе, загрузке ZIP, PWA-билдере и `Custom PWA`; у `Destination` — во всех способах создания. `Advertiser` открывается через `Settings → Advertisers`.

В ERP карточки открываются через `Tracker → Sources`, `Tracker → Campaigns`, `Tracker → Destinations`. У `Flow` вне типа `Notifications` пул — `Campaign`: `Tracker → Flows → Edit Flow`, левая панель. У `Lander Type` пул — `Landing`: `Content → Landings ▾ → Manage landing types`.

В MTK `Sources`, `Campaigns`, `Destinations` и `Landings` — вкладки верхнего меню. Редактирование `Flow` и `Lander Type` из интерфейса недоступно.

В ремаркетинговой кампании секции `User fields` нет.

`Destination` — шестое значение `Type`, появившееся вместе с этой секцией. Полный список значений и что каждое означает — [models/visit-field.md](../models/visit-field.md).

В Finance- и iGaming-шаблонах тенанта под каждую карточку уже заведены по три свободных поля нужного `Type` в группе `Custom`: `source_field_1…3`, `campaign_field_1…3`, `landing_field_1…3`, `destination_field_1…3` (описание у каждого — `Free <source|campaign|landing|destination>-level field - name it and use it for anything`): переименуйте и используйте под любое значение уровня этой сущности. В Nutra- и Sweeps-шаблонах таких заготовок нет.

В ERP поле под карточку заводится в `Settings → Fields` с нужным `Type`.

Создание нового поля в MTK — [how-to/custom-fields.md](custom-fields.md).

## Как добавить поле в карточку — кнопка `Add field`

Собственные поля добавляются кнопкой `Add field`; родительские строки и уже заполненные легаси-поля могут появиться автоматически. Кнопка `Add field` (`Добавить поле`) под списком открывает поповер с доступными полями и строкой поиска — поиск идёт и по имени поля, и по слагу. Клик по строке добавляет поле в конец списка.

Убрать поле — красная кнопка-минус справа от строки (`Remove field` / `Удалить поле`). Убранное поле возвращается в список поповера.

Удаление строки убирает поле только из формы: уже вписанное значение остаётся сохранённым в карточке и продолжает доезжать до визита. Чтобы значение перестало применяться, сначала очистите инпут и сохраните карточку, и только потом убирайте строку.

Если добавлять больше нечего, кнопки `Add field` в секции нет вовсе. Если кнопка есть, но поиск ничего не нашёл, поповер показывает `All available fields are already added`.

Сохраняется набор вместе с самой карточкой — отдельной кнопки у секции нет.

## Почему нужного поля нет в списке `Add field`

Поповер показывает не все поля тенанта, а срез по четырём условиям — если поля не видно, не выполняется одно из них:

- **`Type` поля не совпадает с пулом карточки.** У `Source` в форме видны только поля `Type = Source`, у `Campaign` и `Flow` — `Campaign`, у лендинга и `Lander Type` — `Landing`, у `Destination` и `Advertiser` — `Destination`.
- **Поле уже добавлено** в эту карточку — оно среди строк, а не в поповере.
- **Поле заархивировано** — архивные в поповер не попадают.
- **Нет доступа к полю.** Пул уважает доступ: предлагаются поля, до которых у вас есть хотя бы уровень `Use` — свои, расшаренные вам или вашей команде, поля участников ниже вас по уровню в команде и поля с `Access type` `Use` или `View`, а при `Scopes` / `Editor Scopes` на поля в позиции (`scopes.settings.fields`, только ERP) — все поля тенанта. Чтобы выбрать поле, открывать его карточку не нужно — уровня `Use` хватает. Все источники доступа — [models/permissions-model.md](../models/permissions-model.md).

Отдельный случай — поле, которое родитель забрал себе режимом «только родитель»: в дочерней форме его нет ни строкой, ни пунктом в поповере.

## Как `Flow`, `Lander Type` и `Advertiser` раздают поля дочерним карточкам

У этих трёх карточек каждая строка `User fields` имеет **режим** — он решает, кто вписывает значение и кто его видит. Режим переключается тремя иконками справа от поля: замок, копия, стрелка. Подпись режима — только в тултипе иконки, текста на кнопке нет.

Пары «родитель → ребёнок» фиксированные: `Flow` → `Campaign`, `Lander Type` → лендинг, `Advertiser` → `Destination`. Лейблы режимов подставляются под пару, поэтому один и тот же режим в разных формах называется по-разному. У `Source` родителя нет — режимов в его форме тоже нет.

Унаследованные строки идут в дочерней форме первыми и отличаются двумя признаками: у них нет кнопки удаления, а тултип показывает происхождение и режим — например `From flow · Campaign template` (`От флоу · Шаблон для кампании`). Родитель выбирается в самой дочерней форме (`Flow` у кампании, `Lander Type` у лендинга, `Advertiser` у `Destination`) — смена родителя меняет и набор унаследованных строк.

### Замок — `Flow only` / `Lander type only` / `Advertiser only`: значение задаётся только в родителе

Поле заполняется исключительно в родительской карточке, в дочернюю форму оно не попадает вовсе — ни строкой, ни пунктом в `Add field`.

На визите побеждает значение родителя. Если у ребёнка от прежних настроек осталось своё значение этого поля, оно отбрасывается и в визит не идёт. Пустое значение у родителя означает, что поле в визит просто не запишется — пустым уже записанное не затирается.

Русские подписи режима: `Только флоу` / `Только тип ленда` / `Только рекламодатель`.

### Копия — `Campaign template` / `Lander template` / `Destination template`: родитель даёт заготовку

Родитель задаёт значение по умолчанию, дочерняя карточка получает поле уже заполненным и может переписать значение на своё. Строка в дочерней форме есть, значение редактируется, удалить строку нельзя — она пришла от родителя.

AIO копирует заготовку при создании дочерней карточки; затем она хранится как собственное значение ребёнка. Открытая форма тоже умеет подставлять заготовку (разбор — секция «Когда подставляется значение из шаблона родителя» этого документа).

Русские подписи режима: `Шаблон для кампании` / `Шаблон для ленда` / `Шаблон для дестинейшна`.

### Стрелка — `Campaign only` / `Lander only` / `Destination only`: значение вводит ребёнок

Родитель только объявляет, что поле должно быть в дочерних карточках. В его собственной форме инпут виден, но нередактируем — значение туда не вводится.

Дочерняя карточка получает пустую строку поля и заполняет её сама; убрать эту строку она не может — поле пришло от родителя.

Русские подписи режима: `Только кампания` / `Только ленд` / `Только дестинейшн`.

## Когда подставляется значение из шаблона родителя (и когда не подставляется)

AIO копирует значение template-поля из родителя **при создании** дочерней карточки. Затем оно хранится как собственное значение ребёнка; подстановка в открытой форме работает отдельно.

Отсюда три следствия:

- **Правка значения в родителе сама по себе не переписывает сохранённые значения** уже созданных кампаний, лендов и дестинейшенов. Однако повторное открытие или смена родителя в форме может подставить заготовку — проверьте инпуты перед сохранением.
- **Введённое в дочерней форме побеждает.** Вписали при создании своё значение — заготовка не применится. Стёртое поле тоже считается осознанным вводом: останется пустым.
- **Если template-поле у родителя пустое**, копировать нечего — ребёнок получит пустую строку.

В форме при смене родителя его заготовки попадают в инпуты, которые ещё не правили вручную в этом открытии. Сохранённое ранее значение само по себе не делает инпут тронутым. Если у существующей дочерней карточки своего значения нет, при открытии форма тоже подставит template-значение родителя. Поэтому очищенный ранее инпут может снова заполниться заготовкой; чтобы сохранить пустое значение, очистите его перед сохранением.

Создание `Destination` способом `By Integration` заготовки `Advertiser` не подставляет вовсе.

## Вписал значение поля в один `Source`, а на новом `Source` оно пустое — дефолта у поля нет

**Значение `User fields` живёт в карточке конкретной сущности, а у определения поля значения по умолчанию нет — поэтому новый `Source` стартует с пустым полем, что бы ни было вписано в соседних сорсах. Новая кампания, лендинг или `Destination` могут получить заготовку от своего родителя.** При регистрации визита AIO читает только карточку того `Source`, через который визит пришёл; переносить настройку с других сорсов неоткуда. У `Source` нет и родителя, который раздавал бы заготовку (в отличие от `Campaign` ← `Flow`, лендинг ← `Lander Type`, `Destination` ← `Advertiser`).

Откройте список `Sources` — в ERP через `Tracker → Sources`, в MTK через вкладку `Sources` верхнего меню. Правый клик по сорсу (или карандаш в строке) → `Edit source` → секция `User fields` → `Add field` → значение → сохранить карточку. Быстрый путь для серии одинаковых сорсов — правый клик → `Copy source`: в форме копии предлагается имя `<имя> copy`; копия забирает и набор полей, и вписанные значения, дальше меняете только то, что отличается.

Новое значение доезжает до визитов не мгновенно: визиты, пришедшие сразу после сохранения, ещё могут получить старое значение. Уже зарегистрированные визиты задним числом не меняются.

## Переключили режим на «только родитель» — старое значение ребёнка в визит не попадёт

Симптом: поле было `Campaign template` или `Campaign only`, в карточке кампании осталось значение, режим у `Flow` переключили на `Flow only` — и на визите это значение больше не появляется.

Так и работает: у поля в режиме «только родитель» источник истины — родительская карточка, значение ребёнка отбрасывается перед записью в визит. Записанное раньше значение остаётся в данных дочерней карточки, но в её форме поле больше не показывается и в визит не идёт.

Что делать: перенести нужное значение в родителя (`Flow`, `Lander Type` или `Advertiser`) либо вернуть режим, при котором значение вводит ребёнок.

## Что происходит с полем, если его заархивировать или удалить

Архивное поле пропадает и из поповера `Add field`, и из строк формы — но в карточке не теряется: и запись в наборе карточки, и записанное значение остаются на месте. После снятия архива строка вернётся в форму с прежним значением.

В ERP снять архив можно через `Settings → Fields → правый клик`.

Вскоре после архивации значение архивного поля из карточки **не пишется в новые визиты**: поле исключено из рабочего набора AIO. Его плейсхолдер `{{aio.visit.fields.<slug>}}` тоже исключён из подстановок — рассчитывать на значение поля в нём нельзя. Снятие архива возобновляет запись — тоже не мгновенно.

Удалённое поле тоже исчезает из формы, а из набора карточки вычищается при ближайшем сохранении.

Значения скрытых строк сохранением не затираются: форма отправляет значения только по тем строкам, которые видит.

## Поле уровня лендинга или `Lander Type` пишется в визит само — SDK-макрос не нужен

Значение, заданное в карточке лендинга или его `Lander Type`, попадает в нетрэш-визит серверной механикой — писать для этого `window.aioBus.push({ type: "trigger", ... })` на лэнде больше не нужно. Так же применяются значения `Source`, `Campaign`, `Flow`, `Destination` и `Advertiser`: они переносятся, когда нетрэш-визит проходит через соответствующую сущность. При переносе полей лендинга и `Destination` с их родителями AIO использует источник `ERP Defined`, а полей `Source`, `Campaign` и `Flow` при регистрации визита — `Agent Init`.

Момент записи, поведение при повторном проходе того же лэнда и порядок, в котором значения перебивают друг друга на визите, — [models/visit-field.md](../models/visit-field.md). Про `window.aioBus` и макросы лэнда — [reference/sdk.md](../reference/sdk.md).

## Форма кампании больше не показывает все поля типа `Campaign`

Раньше карточка кампании рисовала весь пул полей `Type = Campaign`. Теперь в ней только то, что добавлено кнопкой `Add field`, плюс унаследованное от `Flow`.

Кампании, созданные до этого, ничего не теряют: поля, у которых уже есть значение, поднимаются в форму автоматически, даже если набор ни разу не сохраняли. А вот поля с пустым значением из формы пропали — чтобы такое поле заполнить, его нужно добавить плюсиком заново.

Пустое значение в поле по-прежнему означает «удалить значение», а не «оставить как было».

## Вписал значение в карточку, а колонки поля в таблице нет

**Колонка пользовательского поля в таблицах настроечных сущностей скрыта по умолчанию независимо от флага `Is Visible` — её добавляют настройкой колонок таблицы — кнопка `Settings` в тулбаре таблицы → `Table settings` ([reference/ui-common.md](../reference/ui-common.md)).** Какие таблицы это затрагивает и как включить колонку — [how-to/custom-fields.md](custom-fields.md).

На визит значение при этом доезжает как обычно: проверьте его в таблице `Visits` — в ERP через `Tracker → Visits`, в MTK через вкладку `Visits` верхнего меню.
