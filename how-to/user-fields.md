# User fields — поля визита прямо в карточках Source, Campaign, лендинга и Destination

Значение поля визита задаётся не только ссылкой и не только скриптом на лэнде — его можно вписать прямо в карточку настроечной сущности: `Source`, `Campaign`, лендинга, `Destination`, а также их «родителей» — `Flow`, `Lander Type`, `Advertiser`. За это отвечает секция `User fields` (`Пользовательские поля`) в форме.

Само поле сначала заводится в `Settings → Fields` — имя, slug, `Type`, `Format`, `Available Values`: [how-to/custom-fields.md](custom-fields.md). Концепт поля визита, кто в него пишет и в каком порядке значения перебивают друг друга — [models/visit-field.md](../models/visit-field.md).

## Что такое секция `User fields` в карточке сущности

`User fields` — блок в форме сущности со списком полей визита, значения которых задаются прямо в этой карточке. Одна строка блока = одно поле: слева инпут со значением, справа кнопка удаления строки, под списком — кнопка `Add field`.

Набор полей формы и сами значения хранятся раздельно. Набор — это «какие поля вообще показывать в этой карточке», значения — что в них вписано. Порядок строк = порядок, в котором поля добавляли.

Пока в секции ничего не добавлено, она показывает `No fields added yet` (`Поля ещё не добавлены`).

## В какой карточке какие поля доступны — пул задаётся `Type` поля

В форму попадают только поля с подходящим `Type`, у каждой карточки свой пул. Родительская сущность работает с пулом своего ребёнка: у `Flow` это поля `Campaign`, у `Lander Type` — `Landing`, у `Advertiser` — `Destination`.

| Карточка | Где открыть | Пул полей (`Type`) |
|---|---|---|
| `Source` | `Tracker → Sources` | `Source` |
| `Campaign` | `Tracker → Campaigns` | `Campaign` |
| `Flow` | `Tracker → Flows → Edit Flow`, левая панель | `Campaign` |
| лендинг | форма лэнда в редакторе, загрузка ZIP, генерация, PWA-билдер | `Landing` |
| `Lander Type` | `Content → Landings ▾ → Manage landing types` | `Landing` |
| `Destination` | `Tracker → Destinations`, все способы создания | `Destination` |
| `Advertiser` | `Settings → Advertisers` | `Destination` |

`Destination` — шестое значение `Type`, появившееся вместе с этой секцией. Полный список значений и что каждое означает — [models/visit-field.md](../models/visit-field.md).

## Как добавить поле в карточку — кнопка `Add field`

Поле попадает в форму только вручную. Кнопка `Add field` (`Добавить поле`) под списком открывает поповер с доступными полями и строкой поиска — поиск идёт и по имени поля, и по слагу. Клик по строке добавляет поле в конец списка.

Убрать поле — красная кнопка-минус справа от строки (`Remove field` / `Удалить поле`). Убранное поле возвращается в список поповера.

Удаление строки убирает поле только из формы: уже вписанное значение остаётся сохранённым в карточке и продолжает доезжать до визита. Чтобы значение перестало применяться, сначала очистите инпут и сохраните карточку, и только потом убирайте строку.

Если добавлять больше нечего, кнопки `Add field` в секции нет вовсе. Если кнопка есть, но поиск ничего не нашёл, поповер показывает `All available fields are already added`.

Сохраняется набор вместе с самой карточкой — отдельной кнопки у секции нет.

## Почему нужного поля нет в списке `Add field`

Поповер показывает не все поля тенанта, а срез по четырём условиям — если поля не видно, не выполняется одно из них:

- **`Type` поля не совпадает с пулом карточки.** У `Source` в форме видны только поля `Type = Source`, у `Campaign` и `Flow` — `Campaign`, у лендинга и `Lander Type` — `Landing`, у `Destination` и `Advertiser` — `Destination`.
- **Поле уже добавлено** в эту карточку — оно среди строк, а не в поповере.
- **Поле заархивировано** — архивные в поповер не попадают.
- **Нет доступа к полю.** Пул уважает доступ: предлагаются поля, которыми вы владеете, которые вам расшарили или у которых `Access Type = Everyone` ([how-to/permissions.md](permissions.md)).

Отдельный случай — поле, которое родитель забрал себе режимом «только родитель»: в дочерней форме его нет ни строкой, ни пунктом в поповере.

## Как `Flow`, `Lander Type` и `Advertiser` раздают поля дочерним карточкам

У этих трёх карточек каждая строка `User fields` имеет **режим** — он решает, кто вписывает значение и кто его видит. Режим переключается тремя иконками справа от поля: замок, копия, стрелка. Подпись режима — только в тултипе иконки, текста на кнопке нет.

Пары «родитель → ребёнок» фиксированные: `Flow` → `Campaign`, `Lander Type` → лендинг, `Advertiser` → `Destination`. Лейблы режимов подставляются под пару, поэтому один и тот же режим в разных формах называется по-разному. У `Source` родителя нет — режимов в его форме тоже нет.

Унаследованные строки идут в дочерней форме первыми и отличаются двумя признаками: у них нет кнопки удаления, а тултип показывает происхождение и режим — например `From flow · Campaign template` (`От флоу · Шаблон для кампании`). Родитель выбирается в самой дочерней форме (`Flow` у кампании, `Lander Type` у лендинга, `Advertiser` у `Destination`) — смена родителя меняет и набор унаследованных строк.

### Замок — `Flow only` / `Lander type only` / `Advertiser only`: значение задаётся только в родителе

Поле заполняется исключительно в родительской карточке, в дочернюю форму оно не попадает вовсе — ни строкой, ни пунктом в `Add field`.

На визите побеждает значение родителя. Если у ребёнка от прежних настроек осталось своё значение этого поля, оно отбрасывается и в визит не идёт. Пустое значение у родителя означает, что поле в визит просто не запишется — пустым уже записанное не затирается.

Русские подписи режима: `Только флоу` / `Только тип ленда` / `Только рекламодатель`.

### Копия — `Campaign template` / `Lander template` / `Destination template`: родитель даёт заготовку

Родитель задаёт значение по умолчанию, дочерняя карточка получает поле уже заполненным и может переписать значение на своё. Строка в дочерней форме есть, значение редактируется, удалить строку нельзя — она пришла от родителя.

Ключевая деталь — момент подстановки: заготовка копируется только при создании дочерней карточки, дальше это обычное собственное значение ребёнка (разбор — секция «Когда подставляется значение из шаблона родителя» этого документа).

Русские подписи режима: `Шаблон для кампании` / `Шаблон для ленда` / `Шаблон для дестинейшна`.

### Стрелка — `Campaign only` / `Lander only` / `Destination only`: значение вводит ребёнок

Родитель только объявляет, что поле должно быть в дочерних карточках. В его собственной форме инпут виден, но нередактируем — значение туда не вводится.

Дочерняя карточка получает пустую строку поля и заполняет её сама; убрать эту строку она не может — поле пришло от родителя.

Русские подписи режима: `Только кампания` / `Только ленд` / `Только дестинейшн`.

## Когда подставляется значение из шаблона родителя (и когда не подставляется)

Значение template-поля копируется из родителя в ребёнка **только в момент создания** дочерней карточки. Дальше это обычное собственное значение ребёнка.

Отсюда три следствия:

- **Правка значения в родителе задним числом ничего не меняет** у уже созданных кампаний, лендов и дестинейшенов — значение придётся править у них самих.
- **Введённое в дочерней форме побеждает.** Вписали при создании своё значение — заготовка не применится. Стёртое поле тоже считается осознанным вводом: останется пустым.
- **Если template-поле у родителя пустое**, копировать нечего — ребёнок получит пустую строку.

В самой форме подстановка работает мягче: при смене родителя его заготовки попадают только в те инпуты, которых ещё не касались руками, уже введённое не перетирается.

Создание `Destination` способом `By Integration` заготовки `Advertiser` не подставляет вовсе.

## Переключили режим на «только родитель» — старое значение ребёнка в визит не попадёт

Симптом: поле было `Campaign template` или `Campaign only`, в карточке кампании осталось значение, режим у `Flow` переключили на `Flow only` — и на визите это значение больше не появляется.

Так и работает: у поля в режиме «только родитель» источник истины — родительская карточка, значение ребёнка отбрасывается перед записью в визит. Записанное раньше значение остаётся в данных дочерней карточки, но в её форме поле больше не показывается и в визит не идёт.

Что делать: перенести нужное значение в родителя (`Flow`, `Lander Type` или `Advertiser`) либо вернуть режим, при котором значение вводит ребёнок.

## Что происходит с полем, если его заархивировать или удалить

Архивное поле пропадает и из поповера `Add field`, и из строк формы — но не теряется: и запись в наборе карточки, и записанное значение остаются на месте. Снимете архив (`Settings → Fields → правый клик`) — строка вернётся в форму с прежним значением.

Удалённое поле тоже исчезает из формы, а из набора карточки вычищается при ближайшем сохранении.

Значения скрытых строк сохранением не затираются: форма отправляет значения только по тем строкам, которые видит.

## Поле уровня лендинга или `Lander Type` пишется в визит само — SDK-макрос не нужен

Значение, заданное в карточке лендинга или его `Lander Type`, попадает в визит серверной механикой — писать для этого `window.aioBus.push({ type: "trigger", ... })` на лэнде больше не нужно. Так же работают `Source`, `Campaign`, `Flow`, `Destination` и `Advertiser`: значение из карточки доезжает до визита, когда визит проходит через эту сущность. Источник записи у таких значений — `ERP Defined`.

Момент записи, поведение при повторном проходе того же лэнда и порядок, в котором значения перебивают друг друга на визите, — [models/visit-field.md](../models/visit-field.md). Про `window.aioBus` и макросы лэнда — [reference/sdk.md](../reference/sdk.md).

## Форма кампании больше не показывает все поля типа `Campaign`

Раньше карточка кампании рисовала весь пул полей `Type = Campaign`. Теперь в ней только то, что добавлено кнопкой `Add field`, плюс унаследованное от `Flow`.

Кампании, созданные до этого, ничего не теряют: поля, у которых уже есть значение, поднимаются в форму автоматически, даже если набор ни разу не сохраняли. А вот поля с пустым значением из формы пропали — чтобы такое поле заполнить, его нужно добавить плюсиком заново.

Пустое значение в поле по-прежнему означает «удалить значение», а не «оставить как было».
