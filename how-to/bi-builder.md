# BI Builder — свой дашборд из виджетов

**BI Builder — это конструктор кастомных дашбордов: собираешь свою страницу из чарт-виджетов поверх метрик тенанта, раскладываешь их по сетке и разбиваешь по табам.** В отличие от штатного `Dashboard` (`/app/dashboard` — фиксированная сводка по тенанту, см. [reference/ui-map.md](../reference/ui-map.md)), тут раскладку, набор чартов, метрики и группировки задаёшь сам.

Открывается из меню `Analytics → BI Builder`, роут `/app/analytics/bi-builder`. Доступ управляется permission `analytics.charts-builder` — если его нет, пункта в меню не будет.

---

## Что можно собрать: табы и виджеты

Дашборд состоит из **табов**, внутри каждого таба — **виджеты-чарты** на 12-колоночной сетке. Каждый виджет тянет данные из метрик тенанта за выбранный период.

- **Табы** — как вкладки: несколько дашбордов в одном месте. Добавить — `+` в баре табов, переименовать — двойной клик по названию, закрыть — крестик (последний таб закрыть нельзя). Первый таб по умолчанию называется `Cool Dashboard`.
- **Виджеты** — двигаются и меняют размер мышкой (перетаскивание за хедер, ресайз за угол). При наложении соседние виджеты автоматически сдвигаются вниз, не перекрываются.
- Раскладка **не сохраняется автоматически** — после правок в тулбаре появляется `Save`; рядом `Discard` откатывает несохранённые изменения к последнему сохранённому состоянию.

## Как добавить чарт-виджет

Кнопка **`New chart`** в тулбаре открывает диалог нового виджета. Задаёшь:

- **Title** — название карточки (если пустое, подставится имя типа).
- **Chart type** — тип визуализации (см. ниже).
- **Metric(s)** — одна или несколько метрик из каталога тенанта. Типы `Number` и `Rank list` работают только с одной метрикой.
- **Group by** — группировка (страна, кампания, дата и т.п.); кнопка `Pick a grouper` открывает каталог групперов трекера (разбор — «Какие группировки доступны в New chart и на карточке BI Builder» ниже). Для `Number` и `Funnel` группировка не применяется; остальные типы её используют.
- **Color** — цвет акцентной полоски карточки.
- **Compare** — добавить сравнение со встречным периодом (доступно не для всех типов, см. ниже).

Метрику и группировку можно менять прямо на карточке — через инлайн-теги в хедере виджета. Тип меняется через `Edit` в меню карточки: он открывает диалог настроек. В меню также есть `Duplicate` (копия виджета) и `Remove`; отдельная кнопка в хедере перезагружает данные.

### Какие группировки доступны в New chart и на карточке BI Builder

В диалоге `New chart` и инлайн-пикере карточки BI Builder предлагаются **только групперы трекера** — категории `Funnel` / `Tracker` / `Location` / `Landings` / `Destinations` / `Variants` / `Client` / `Device` / `OS` / `Time` / `Browser` / `Other`, поля тенанта, доступные как группер (категория `Fields` либо группа, заданная у поля) и позиционные категории рассылок трекера (`RMK Audience #1`…`#3` и остальные `RMK …`). Группировки других разделов — `Facebook`, `Google` и событийные группировки раздела `Marketing` (категория `Remarketing`: `Campaign` / `Flow` / `Templates` / `Channel` / `Send Result`, плюс их собственная категория `Time` с разрезами `Day` / `Hour` / `Month` / `Year`) — в BI Builder не предлагаются ни в диалоге чарта, ни на карточке. Эти два пикера используют подмножество общего каталога: Meta-группировки и группировки событий отправки из раздела `Marketing` в них не выбрать. За такими разбивками идите в таблицы `Meta → …` и раздел `Marketing` ([how-to/analytics.md](analytics.md)).

### Как выбрать или снять группировку виджета — пикер `Pick a grouper`

Пикер группировки в BI Builder — тот же каталог групперов, что и у таблиц: категории с иконками, поиск по имени, блок избранного сверху, позиционные серии (`Landing 1..3` и т.п.) с выбором позиции или роли-типа (как устроен каталог — [how-to/analytics.md](analytics.md)). Снять группировку — отдельной кнопкой: крестик на теге группировки в хедере карточки (тултип `No group`) или кнопка-корзина рядом с кнопкой `Pick a grouper` в диалоге чарта.

### Типы чартов

Доступные типы (сгруппированы в диалоге):

- **Column** / **Stacked** — столбчатые (обычный и с накоплением).
- **Line** / **Area** — линейный и с заливкой.
- **Pie** / **Treemap** — доли и вложенные площади.
- **Number** — одно число (тотал метрики), с мини-спарклайном.
- **Top Table** / **Rank list** — таблица-топ и рейтинг-список.
- **Funnel** — воронка.

`Column`, `Line`, `Stacked`, `Area` — временные ряды: по оси времени раскладываются автоматически, а выбранная группировка становится разбивкой серий поверх времени. **Compare** поддержан на `Line`, `Area`, `Column`, `Stacked`, `Number`, `Top Table` — на остальных типах тумблер выключается.

## Старт с шаблона: пустой таб предлагает готовые дашборды

В пустом активном табе показывается **пикер шаблонов** — набор преднастроенных дашбордов под вертикаль плюс карточка `Empty dashboard` (начать с нуля). Выбор `Empty dashboard` скрывает пикер для этого таба; дальше виджеты добавляются через `New chart`.

Есть шаблоны для вертикалей sweepstakes, gambling, nutra, finance. Каждый несёт готовый набор чартов с плейсхолдер-метриками (условными именами вместо конкретных UUID).

При выборе шаблона открывается диалог маппинга: плейсхолдеры метрик сопоставляются с доступными метриками **твоего** тенанта, а плейсхолдеры группировок — с общим каталогом групперов. Система пытается подставить совпадения по имени автоматически; незамапленные слоты нужно выбрать вручную — пока не заполнены все, кнопка `Apply template` неактивна. После применения чарты со своими позициями раскладываются в активный таб.

Плейсхолдеры в основном названы именами метрик из шаблона тенанта той же вертикали (`Visits`, `Leads`, `Registrations`, `CR %`, `Revenue $`, `Profit $`, `ROI %`, `CPL $`…), поэтому в тенанте, где засеянные метрики не переименовывали, большинство слотов подставляется само. Подбор идёт по имени: сначала точное совпадение без учёта регистра, иначе первая метрика, чьё имя содержит имя плейсхолдера или содержится в нём, — поэтому слот `Lead` может подхватить любую метрику со словом `Lead` в имени (`Leads`, `Approved Leads`…), а слот с именем, которого в тенанте нет (например `LP #1 Visits` при засеянной `LP1 Visits`), — другую метрику по вхождению. Маппинг перед `Apply template` стоит просмотреть глазами; переименованная или удалённая метрика без похожего имени оставляет слот пустым — его выбирают руками. Эти дашборд-шаблоны встроены в продукт и с шаблоном тенанта не связаны: набор одинаков у всех тенантов.

## Фильтры и период: тулбар дашборда

Тулбар управляет тем, за что и по каким срезам считаются все виджеты таба:

- **Период** — пресеты (Today / Yesterday / This week / Last week / This month / Last month) или произвольный диапазон. Меняет данные всех виджетов.
- **Compare** (страничный) — включает встречный период для всего таба сразу; можно и точечно на отдельном виджете.
- **Cross-filter** — тумблер (по умолчанию включён): фильтрация **интерактивно, кликом по данным выбранной группировки**. Клик по строке `Top Table` / `Rank list` или по элементу группировки в графике добавляет его значение в общий фильтр и пересчитывает виджеты таба. Без группировки такой клик не фильтрует. Повторный клик по тому же значению снимает его; при выключенном тумблере клики по данным не фильтруют. Кнопка `Reset Filters` сбрасывает фильтр; её счётчик показывает число отфильтрованных полей.
- **Event Attribution** — тумблер атрибуции конверсий по времени события.
- **Auto-refresh** — авто-перезагрузка данных каждые 30 секунд; рядом кнопка ручного обновления.

Доступные метрики берутся из каталога тенанта, а группировки — из общего каталога с полями тенанта. В `New chart` и на карточке предлагаются только трекерные группировки (секция «Какие группировки доступны в New chart и на карточке BI Builder» выше).

## Как поделиться дашбордом: share-код

Кнопка `Share` в тулбаре генерирует **код-строку** для активного таба (нужен хотя бы один виджет). Код можно скопировать и передать другому пользователю этого же тенанта; получатель вставляет его в том же диалоге `Share` — и таб импортируется как новая вкладка со всеми виджетами.

- Код — короткая строка из 8 символов.
- Созданный через `Share` код не имеет срока истечения. Для кода, которому задан срок и он уже истёк, при вставке показывается `Code expired`; для несуществующего или недоступного в текущем тенанте — `Code not found`.
- Ранее выпущенные коды видны списком `My codes` в диалоге (имя, число чартов, дата) — их можно удалять.

*Импорт создаёт новый таб с копиями виджетов; исходный дашборд у автора не меняется.*

## Кому доступен BI Builder

Страница BI Builder в ERP открывается по permission `analytics.charts-builder`: право определяет видимость пункта меню и доступ к странице. Если запрос данных получает HTTP `403`, карточки показывают `BI API not enabled for this account`. Причину отказа этот текст не называет: если право в Position есть, а карточки всё равно показывают эту ошибку, напишите в чат команде AIO.
